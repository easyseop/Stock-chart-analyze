## 1. 직전 라운드 평가 수용

Codex V2 판정의 요지 — *"백엔드 한 틱 계산에서는 닫혔지만, 사용자 화면과 장기
누적 계약까지 포함하면 아직 닫히지 않았다"* — 를 그대로 수용한다. `None`이라는
새 계약을 만들어 놓고 그 계약의 **소비자를 한 곳도 고치지 않은 것**, 그리고
미확정 하루를 역사에서 지워 **전후 정상일을 연속 복리되게 둔 것**이 V2의
잘못이었다.

## 2. Codex 지적별 대응 (`759b41ad`)

### P1-1 `None` 소비자 전파 + 저장 순서

| 소비자 | 수정 |
|---|---|
| `_fmt` / `_vs_line` / `_mid_alert` | `None` → "미확정"/"판정 보류" — 초과수익·색상 판정 없음 |
| 텔레그램 `/성과` | 미확정 분기 추가(예외 제거) |
| 사이트 히어로(`updateHero`) | `optionalNumber` 사용 — `null → +0.0%` 강등 금지, "미확정" 표시 |
| TWR 카드 | 색상은 `optionalNumber` 기준, 미확정 시 안내 문구 |
| `perf.html` | `f()`/`cls()` null 분기 · KPI "판정 보류" · **선은 null 구간을 잇지 않고 공백**(pen-up) |
| `dashboard_snapshot` | `float(acct or 0)` 제거 — `None`·`quality`·`unresolved_keys` 그대로 전파 |

저장 순서: 장중 틱과 마감 모두 **상태를 원자 저장한 뒤** 네트워크(텔레그램·
QuickChart·ntfy)를 수행하고 네트워크 예외는 삼킨다. Codex가 지적한 "알림
예외가 격리·표본·sampled_at 저장을 날려 매 사이클 같은 격리를 반복"하는
경로를 제거했다.

### P1-2 키별 마감·carry

- `days[]` 행이 `acct`/`a`/`b`를 **키별로** 숫자 또는 `None`으로 기록한다.
  A만 미확정이면 계좌·B는 숫자로 남는다.
- `carry["unresolved"]`가 불리언에서 **키 집합**이 됐다. 다음 세션은 미확정
  키만 첫 표본으로 재시작하고 정상 키는 기준선을 이어받는다. `account`가
  미확정이었을 때만 전체 `first_sample`(계좌-지수 기간 정합 때문).
- 구버전 상태(`unresolved: true`)는 전체 키 집합으로 해석(호환).
- 마감 문구는 미확정 키를 이름(계좌/전략A/전략B)으로 명시하고 정상 키의
  확정값을 함께 보여준다.

### P1-3 품질 행 — 미확정 하루가 역사에서 사라지지 않는다

- **모든 마감일**이 `days[]`에 남는다: `quality` ∈ ok/pending/unresolved/partial,
  `unresolved_keys`, 키별 값(의심 키는 `None`).
- 소비 측 복리 차단:
  - 사이트 기간 누적(1m/3m/전체): 선택 기간에 해당 키의 `None` 행이 하나라도
    있으면 **그 키 전체를 숫자로 확정하지 않고** "미확정 N일 · 기간 누적
    비확정"을 표시(기존 보유 동일가중의 부분수집 처리와 같은 패턴).
  - `perf.html` 누적 알파: 단절 이후 잇지 않음(broken flag).
  - `capture_stats`: 품질 행 제외 + **제외 일수 명시**(편향 가시화 — V2 §4-6
    자기지적 대응).

### P2-1 reanchor 임계구역

미리보기 외의 apply 경로는 **잠금 획득 → 최신 상태 재읽기 → 세션 존재·미마감
검증 → 백업(pid 포함 고유명) → 변경 → 저장**을 한 임계구역에서 수행한다.
마감된 세션은 거부한다.

### P2-2 잠금 블로킹

`state_lock(timeout_s=10)` — `LOCK_NB` 폴링으로 바꿔 초과 시 `TimeoutError`.
`tick()`은 그 경우 **성과 틱만 건너뛰고**(1회 경보) 매수 사이클을 막지 않는다.

### P2-3 품질 원장

`bot/alpha_quality.jsonl`(append-only·0600·gitignore·로컬 전용)에 hold/
quarantine 이벤트의 원본 수치와 미확정 마감의 `anomaly_log` 꼬리를 영속한다.
행에는 시각·시장·세션 날짜·정산 여부·**미회계 주문 수**·보유 종목 수·환율이
들어간다. 공개 API에는 `quality`/`unresolved_keys`만 나간다.

### P2-4 테스트

- `None` 소비자(장중 알림·/성과·스냅샷) 3건, 키별 마감·승계 1건, 품질 행
  보존 2건, 캡처 제외 표기 1건 추가.
- Codex 지적대로 `account=A+B` 불변식을 어기던 슬리브 독립 테스트 입력을
  현실적 구성(A가 계좌의 10%)으로 교체.
- 계약이 바뀐 기존 테스트 3건(미정산 마감/부분 세션/carry bool)을 새 계약으로
  갱신. 전체 49/49 통과.

## 3. 남은 격차 — 정직하게

1. **미회계 주문의 key 목록·잔고 출처(직접/캐시)는 품질 원장에 아직 없다**
   (미회계 **수**만 있음). Codex P2-3 요구의 부분 이행이다.
2. **세그먼트 ID는 도입하지 않았다.** "미확정 다음 날 새 세그먼트 + '재시작
   이후' 표시" 대신 "기간에 미확정이 섞이면 그 키 숫자 비확정"을 택했다.
   숨기는 것보다 명시가 낫다고 봤지만, 사용자가 미확정 이후 구간의 유효한
   누적을 보고 싶을 때 불편하다. 격리가 잦으면 재고해야 한다.
3. **한계값(3%/10%/3틱) 근거는 여전히 없다** — 실데이터 필요(V2 §4-4 그대로).
4. **웹 렌더 테스트는 없다.** JS는 `node --check`와 코드 리뷰 수준이다.
   `perf.html`/`app.js`의 실제 렌더에서 반례를 찾아주기 바란다.
5. `nav_inputs`의 두 소스 통합(근본 해법)은 이번에도 범위 밖.

## 4. 검토자가 확인해 줄 것

- P1-1: 남은 `None` 소비자가 있는지 전수 확인(특히 사이트의 today 경로,
  `chart_url`, `performanceInsights`, 드로다운 계산).
- P1-2: A 미확정 마감 → 다음 세션에서 계좌 basis=previous_close·A만
  first_sample일 때 **첫 틱 A interval 계산이 기준선 없음을 안전 처리**하는지.
- P1-3: 품질 행 도입으로 `days[]`를 읽는 다른 소비자(advisor·lookup 등)가
  깨지는 곳이 있는지.
- P2-1: reanchor 임계구역이 미리보기→apply 사이 변화를 정말 막는지.
- P2-2: timeout 10s가 정당한지, 건너뛴 틱의 누락이 다른 가정과 충돌하는지.
- 이 변경들이 주문 경로에 영향이 없는지(alpha는 보고 전용).

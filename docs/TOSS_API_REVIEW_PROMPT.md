## 0. 배경 (이것만 알면 됨)

- 차트 기반 자동매매 시스템(현재 **가상 모의투자** 단계). 전략=52주 저점권
  하락→상승 전환 초입 매수, ATR 손절, 손익비 1:2, 일봉 기준 스윙(초단타 아님).
- 인프라: GitHub Actions(무료 배치)로 5,400종목 스캔·렌더·자동매매 1스텝. 시세는
  현재 **야후/Stooq 무료(15분~수분 지연)**. 신뢰성 보강으로 fast 차선(매매만
  ~3분)+Cloudflare Worker 발사·검증+파수꾼(sentinel, 손절 전담 dry-run 완성)까지
  구축함. 계좌는 원자적 저장+state 브랜치 백업.
- **지금 사용자가 토스증권 계좌 + Open API 앱키를 발급받음.** 실시간(에 가까운)
  시세와 실계좌 자동매매로 넘어가려 한다.

## 1. 토스 Open API — 우리가 파악한 사실 (검증 요청)

| 항목 | 이해 |
|---|---|
| Base URL | `https://openapi.tossinvest.com` |
| 인증 | OAuth 2.0 Client Credentials(서버 간, 사용자 로그인 없음), `Authorization: Bearer`, 계좌 호출은 `X-Tossinvest-Account` 추가 |
| 토큰 | 만료 ~1시간, 50분경 선제 갱신 권장 |
| 시세 | REST 폴링(웹소켓 미공개), 국내+미국 지원 |
| Rate limit | 시세 분당 수백 건 / 계좌 조회 초당 1건(최빡) / 주문 초당 1~10건, 과도 시 무통보 제한 |

→ **Q1. 이 이해에 사실 오류나 빠진 제약이 있나?** (특히 미국주 시세의 지연/정규장
외 처리, 토큰 동시성, 계좌 초당 1건이 폴링 설계에 주는 제약)

## 2. 설계 — 3중 루프 (실매매 시)

```
[서버 상시]
 루프A 시세→전략 (1분)   : 토스 배치 시세 → 지표/게이트 → 자동매매 판단
 루프B 주문 집행 (이벤트) : 진입/청산이면 집행 직전 재조회 → 주문 → 원장
 루프C 파수꾼 (10~20초)   : 보유 손절선 감시·매도. 브로커 서버측 stop은 매수 직후 등록
[GitHub 무료] 풀스캔·렌더·Pages(화면, 매매와 분리)
```

**Rate 예산(우리 규모)**: 보유 4+후보 80=시세 ~84건/분(초당 1.4) ≪ 분당 수백;
계좌 폴링당 1건 ≤ 초당 1; 주문 하루 ≤3건. → 한도 여유라고 본다.
→ **Q2. 이 예산 계산이 맞나? 계좌 초당 1건 한도에서 파수꾼(10~20초 폴링)이
계좌를 매번 조회하면 루프A/B와 합쳐 초당 1건을 넘기지 않나? 조회 종류별
(시세 vs 계좌) 한도가 독립인지 합산인지에 따라 설계가 갈린다.**

## 3. 매매 시 시세·안전장치 (경계 장애 방어 — 이미 반영)

- 주문 직전 단건 시세 재조회(quote_ts 나이>10~30초면 손절 판단 금지)
- 브로커 실보유 재조회(intended_qty ≤ available), 부분체결 시 브로커가 진실
- timeout=UNKNOWN(재주문 금지, open orders 대사 후 잔여만)
- 멱등키 `{broker}:{account}:{symbol}:{opened_at}:{seq}:{action}:{stop_version}`
- 파수꾼 내부 stop 래칫(feed 낡아도 마지막 확정 stop 집행)
- 토큰 만료=P0, 장전 preflight, P0 알림 텔레그램+ntfy 이중화
- 0차 방어=브로커 서버측 stop/조건주문(지원 시 매수 직후 등록)

→ **Q3. 위 방어에서 토스 API 특성상 안 통하거나 추가로 필요한 게 있나?**
(예: 토스가 서버측 stop을 지원하지 않으면? 미국주 주간거래/시간외 체결 처리?
토스 주문 응답의 UNKNOWN을 어떻게 판별하나? 주문 id 멱등을 토스가 지원하나?)

## 4. 도입 순서 (리스크 0 → 확대)

Stage0 시세만 읽기(주문 가상, 리스크 0) → Stage1 그림자(시세+계좌 조회, 주문 가상,
2주+) → Stage2 마이크로(실주문 0.1~0.25%, 동시 1~2종목, 하루 1건, 한 시장) →
Stage3 제한 → Stage4 정상(주문 50~100건 무사고+장애주입 통과 후 1%).

→ **Q4. 이 단계·통과기준이 적절한가? 특히 "시세만 먼저(Stage 0)"가 실효가 있나,
아니면 그림자(계좌 조회 포함)부터 바로 가야 하나?**

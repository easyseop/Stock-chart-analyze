# 익절 사후추적 설계

## 목적

안정적으로 수익을 확정한 뒤 주가가 더 오르는 사례를 모아, 청산을 너무 일찍 한
공통 조건이 있는지 검토한다. 이 결과는 당장 주문 규칙을 바꾸는 신호가 아니라
청산 정책을 개선하기 위한 읽기전용 관찰 자료다.

## 계산 기준

수익 매도마다 해당 거래소 기준 다음 세션부터 1·3·5·10·20거래일을 추적한다.
미국 체결은 거래이력의 KST 날짜를 그대로 쓰지 않고 뉴욕 날짜로 바꿔 첫 사후
세션을 하루 건너뛰지 않게 한다. 체결 세션의 일봉 고가는 매도 이전 고가일 수
있으므로 사후 상승에 포함하지 않는다.

- 평단 대비 총 상승률: `(사후 최고가 / 매도 직전 평단가 - 1) × 100`
- 익절 뒤 평단 기준 추가 수익률: `(사후 최고가 - 익절가) / 평단가 × 100`
  - 원래 포지션 수익률에 몇 `%p`가 더 붙었는지 보여준다.
- 매도가 대비 놓친 상승률: `(사후 최고가 / 익절가 - 1) × 100`
- 기간 말 종가 변화: `(N거래일 종가 / 익절가 - 1) × 100`
- 매도 뒤 최대 하락: `(기간 중 최저가 / 익절가 - 1) × 100`

기간이 아직 지나지 않았으면 `관측일/N일`로 표시하고 완료 표본 통계에는 넣지
않는다.

## 데이터 품질

현재 legacy 이관 전 익절 10건은 체결 사실은 잔고로 확인됐지만 매도 가격이
구버전 주문가 복원값이다. 이 이벤트는 `추정가 참고`로 개별 표시하되 공통점
통계에서는 제외한다. 이후 브로커 체결가가 확인된 이벤트만 확정 표본이다.

공통점은 전략 A/B, 청산 사유, 부분/전량익절, 익절 당시 수익률 구간별로 나눈다.
같은 묶음의 완료된 확정 표본이 최소 3건일 때만 화면에 결론으로 표시한다.
표본이 적을 때는 `표본 수집 중`으로 남겨 우연을 규칙으로 오인하지 않는다.

## 아키텍처와 안전 경계

1. `bot.trade_history`가 확정 체결 원장으로 수익 매도를 만든다.
2. 별도 `post-exit-refresh.service`가 공개 일봉만 갱신한다.
3. 분석 결과를 `/var/lib/stock-post-exit/snapshot.json`에 fsync·원자 교체로
   발행한다.
4. 개인 웹의 `/api/post-exit.json`은 발행 JSON만 읽는다.
5. 브라우저는 내 자산의 `익절 사후추적` 탭에서 기간·가격 품질을 필터링한다.

분석 서비스에는 `kis.env`를 주입하지 않는다. KIS, 주문, kill-switch 모듈을
import하지 않으며, Nice/CPU/Memory 제한을 둬 파수꾼·매수루프와 자원을
경합하지 않는다. 분석 실패나 JSON 손상은 화면만 `사용 불가`가 되고 주문·보호
매도에는 영향을 주지 않는다.

## 운영 주기

Oracle timer는 한국과 미국 장 마감 뒤인 매일 07:30·17:30 KST에 실행한다.
처음 설치할 때 한 번 수동 실행해 기존 수익 매도 종목을 백필한다. 이후 일봉은
증분 갱신한다.

이 데이터로 청산 규칙을 바꾸려면 최소 20거래일 완료 확정 표본을 모으고,
기존 `+1R 절반익절 + 잔량 트레일` 대비 최대낙폭·총R·보유기간을 별도
백테스트한 뒤 다시 승인받는다.

# 재검토 요청 — KIS 주문 보호 P0 수정

> 이 문서는 첫 P0 묶음 검토 당시의 기록이다. 이후 P1·P2·P3와 추가 방어까지
> 모두 반영한 최종 검토 범위는 `docs/ORDER_SAFETY_FINAL_REVIEW.md`를 사용한다.

## 목적

`검토보고서_주문경합_총시드_손절.md`가 판정한 P0 4건(D/E/F/J-b)을 수정한 로컬
변경을 적대적으로 재검토해 달라. 수익률·화면 취향이 아니라 아래 불변식이 어떤
응답 순서와 프로세스 재시작에서도 깨지지 않는지가 기준이다.

- 주문 접수(ACK)는 체결이 아니다.
- 미체결 BUY가 있어도 이미 체결된 보유의 손절을 포기하지 않는다.
- BUY 취소 접수와 취소 확정을 구분한다.
- 매도수량은 공개 feed나 총보유가 아니라 주문 직전 KIS 매도가능수량 이하이다.
- 손절선 출처가 모호하면 추측하지 않고 동결·경보한다.

assertion이 실제 위험을 잡는지 확인해 달라.

## 반드시 반증할 시나리오

### 1. BUY 잔량과 손절 경합

1. BUY 10주 ACK
2. 6주 부분체결, 4주 미체결
3. 가격이 손절선 이탈
4. BUY 잔량 취소 요청은 접수됐지만 브로커 미체결 목록에 아직 존재
5. 취소 확인 직전/직후 추가 1주 체결
6. 취소 확인 뒤 잔고 또는 매도가능수량 조회가 한 번 실패

확인할 것:

- 취소 확인 전 SELL이 동시에 나가지 않는가
- 추가 체결을 대사한 뒤 실제 매도가능수량만 SELL하는가
- planned/ack/partial/cancel_pending/unknown/ODNO 없음 각각 fail-closed인가
- 취소 요청 응답 유실이 반복 취소나 신규 SELL로 이어지지 않는가
- 국내 시장가와 미국 chase 모두 주문 직전 수량을 다시 제한하는가

### 2. 절반익절 ACK와 부분체결

1. +1R에서 절반 5주 SELL
2. ACK, filled=0
3. 다음 사이클에도 미체결
4. 2주 부분체결 뒤 원주문 종료
5. 나머지 3주 뒤늦게 체결 또는 새 키로 재주문
6. 각 단계 사이 프로세스 재시작

확인할 것:

- 0주 체결에서 `half=True`나 본전 래칫이 생기지 않는가
- 2주만 체결됐을 때 5주를 다시 팔지 않고 3주만 남기는가
- 총 목표수량 확인 뒤에만 half·본전 래칫이 정확히 1회 발생하는가
- 상태 파일 쓰기 직전 크래시에도 원장 키 접두사로 복구되는가
- rejected/cancelled/partial-open/partial-closed가 서로 혼동되지 않는가

### 3. 잔고 선반영과 임시 손절선

1. BUY ACK 원장에는 stop 존재
2. KIS 잔고에는 보유 표시
3. `kis_positions`와 공개 feed에는 아직 종목/stop 없음
4. 같은 종목의 서로 다른 stop 후보 2개도 주입

확인할 것:

- 유일 후보는 “주문 접수 후 대사 중”으로 구분해 임시 보호하는가
- 후보 없음/충돌은 종목 동결과 P0가 발생하고 조용히 제외되지 않는가
- 오래된 종료 주문이 새 포지션의 임시 손절선으로 잘못 선택되지 않는가

### 4. KIS 잔고 실패와 공개 feed 경계

1. KIS 잔고 API가 `None`/EGW00201
2. 공개 paper feed에는 과거 KR 보유 8주와 손절 이탈 가격 존재
3. 마지막 정상 KIS 캐시 없음/60초 이내/60초 초과를 각각 주입
4. 주문 직전 `ord_psbl_qty`가 3, 0, 누락, 조회 실패인 경우를 각각 주입

확인할 것:

- 공개 feed만으로 KIS 매도가 절대 호출되지 않는가
- 짧은 캐시로 감시하더라도 주문 직전 조회가 실패하면 전송 전에 막는가
- 총보유 8주여도 매도가능 3주만 전송하는가
- 0/누락/파싱 오류를 총보유로 보정하지 않는가

### 5. 운영 kill-switch

- `python -m bot.kill 1 "P0 검증"`이 실제 파일에 L1을 영속하는가
- L1에서 `buy_new=False`, `protect_sell=True`인가
- 사유 없는 하향이 거부되고 ack 하향만 가능한가
- 상태 파일 쓰기 실패를 성공처럼 표시할 가능성은 없는가

## 회귀·경계 질문

1. `ledger.open_orders/open_order_count`의 side 필터가 기존 UNKNOWN 대사와
   `can_submit`의 동일종목 동시주문 차단을 약화하지 않았는가?
2. 손절을 위해 BUY 계획을 취소한 뒤 buyloop가 같은 계획을 다시 생성할 수 있는가?
3. `kis_exits`의 영속 상태와 주문 원장이 서로 어긋날 때 중복매도 또는 익절 영구누락
   경로가 있는가?
4. KIS 총보유·매도가능수량·봇 claim 중 어느 값이 최종 상한인지 시장별로 일관적인가?
5. 마지막 정상 잔고 캐시 60초가 보호 가용성과 오주문 방지 사이에서 충분히
   fail-closed인가?
6. 신규 코드가 KIS 호출 수를 과도하게 늘려 손절 주문용 유량을 스스로 고갈시키는가?

## 결과 형식

각 발견을 아래 형식으로 작성해 달라.

- `P0~P3`
- 파일·함수·가능하면 줄
- 정확한 재현 순서
- 실제 주문/보호 영향
- 최소 수정안
- 자동 테스트 입력과 기대 출력

P0/P1이 없으면 “없음”만 쓰지 말고 위 5개 시나리오별로 왜 안전한지 상태 전이를
짧게 증명해 달라. 이 검토는 P0 수정 승인 여부만 다룬다. 원 보고서의 P1 12건
(총시드/A·B 귀속/하트비트/레이트리미터/원장 내구성/TWR 등)은 별도 후속 수정
범위이며 아직 해결됐다고 판정하면 안 된다.

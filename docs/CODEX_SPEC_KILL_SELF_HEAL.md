# 구현지시서 — 오인 L1 조건부 자가 복구 (kill self-heal)

작성: Claude, 2026-08-11 17:0x KST
발주·정책 승인: 사용자(2026-08-11 "앞으로 알아서 원인 파악 후 복구시켜 주면
안 돼?") — **"kill 하향은 수동만" 원칙의 좁은 예외를 만드는 정책 변경**이며,
이 승인이 그 근거로 기록된다.
역할: **Codex 구현 → Claude 적대 검토 → 사용자 승인 후 병합** (기존 절차)

---

## 1. 배경

워치독의 자동 L1 상향은 래치라 수동 CLI로만 내려간다. 그 결과 오인 상향
(배포 재시작·API 플래핑발)이 날 때마다 사람이 서버에서 복구해야 했다 —
8/8·8/10·8/11 사흘 연속 실측, 사용자가 서버 접근 불가한 시간대에는 신규
매수가 통째로 빠짐. 사람이 하던 복구 판단(사유 확인 → 서비스 정상 →
readiness GO → 하향)은 이미 기계화 가능한 체크리스트다.

## 2. 자가 복구 조건 — 전부 동시 충족 시에만 L1→L0

S1. **현재 레벨이 정확히 1**이고, kill 상태의 상향 주체(who)가 자동
    주체(watchdog 계열) 화이트리스트에 있으며, 사유(why)가 오인 가능
    계열 화이트리스트(파수꾼 heartbeat 지연/재기동, 잔고 조회 실패 계열)에
    **문자열 계약으로** 일치할 것. operator가 올린 L1·주문 사고 사유는
    영구 제외.
S2. 상향 시각(status ts) 이후 **SELF_HEAL_OBSERVE_S(기본 1800초) 경과** +
    그 관찰 구간 동안 워치독이 본 heartbeat가 **연속 정상**(age < 60s 유지,
    한 번이라도 임계 초과 재발 시 관찰 시계 리셋).
S3. `l1_readiness`를 **프로그램 호출**(scope="l0", fetch_broker=True)한
    결과가 **GO(blockers 0)**. 호출 실패/예외 = 복구 안 함.
S4. **KST 달력일당 최대 1회** — 같은 날 두 번째 자동 상향은 자가 복구하지
    않고 "반복 상향 — 수동 확인 필요" critical 경보. 카운터는 재시작에도
    유지(파일, 0600).
S5. **L2 이상은 어떤 경우에도 자동 하향 없음.** L1→L0만.
S6. 복구 실행은 `kill.lower_level(0, ack="self-heal: <사유·관찰시간·GO요약>")`
    — kill.py의 시그니처·감사 로그 계약을 바꾸지 않는다(호출자 추가일 뿐).
S7. 복구 시 텔레그램 critical 알림: 상향 사유·관찰 시간·readiness GO 요약·
    "오늘 자동 복구 1회 소진, 재상향 시 수동". 전송 실패해도 복구 자체는
    유효(복구가 먼저, 알림은 best-effort — 단 다음 사이클 재시도).

구현 위치: watchdog 프로세스(감시 루프 보유, 이미 kill 상향 권한 있음).

## 3. 주의 (적대 검토 핵심)

- **자가 복구가 진짜 사고를 덮는 경로가 없어야 한다**: S1 화이트리스트는
  포함 방식(기본 거부)이어야 하며, 사유 문자열이 조금이라도 다르면 복구
  금지. 워치독 상향 사유 문자열을 상수로 공유해 계약을 고정할 것(양쪽이
  같은 상수를 import — 자유 문자열 매칭 금지).
- S2 관찰은 **연속성**이 핵심 — 관찰 중 한 번이라도 흔들리면 리셋. 흔들림
  자체가 "오인이 아니라 진행 중 장애"라는 신호다.
- readiness 호출(S3)은 읽기 전용 경로만 사용 — 주문·상태 변이 금지
  (`kis_l1_readiness`의 기존 계약 재사용, 새 조회 로직 작성 금지).
- deploy grace(별도 지시서)와의 상호작용: 유예가 구현되면 오인 상향 자체가
  줄지만, 겹치는 경우에도 관찰 시계는 상향 시각부터 — 이중 단축 금지.
- 자가 복구 루프의 어떤 예외도 워치독 본연의 감시(상향 방향)를 못 깨야
  한다 — self-heal 코드는 try/except로 격리, 실패 시 로그만.
- 하루 1회 카운터·관찰 상태 파일은 0600, 시크릿 금지, 손상 시 fail-closed
  (= 자가 복구 안 함, 수동 절차 상존).
- 이 지시서는 상향 규칙·L2+·operator ack 의무를 바꾸지 않는다.

## 4. 테스트 (최소)

1. 정상 경로: watchdog 상향(화이트리스트 사유) → 30분 연속 정상 + GO →
   자동 L0 + 알림 + 감사 로그(who=self-heal).
2. S1 부정: operator 상향 / 사유 불일치 / L2 → 각각 복구 0.
3. S2 부정: 29분 경과 / 관찰 중 heartbeat 1회 흔들림(리셋) → 복구 0.
4. S3 부정: readiness NO-GO / 호출 예외 → 복구 0.
5. S4: 같은 날 두 번째 자동 상향 → 복구 0 + "수동 확인 필요" 경보 1회.
   다음 KST 날짜에 카운터 리셋.
6. 카운터 파일 손상 → 복구 0(fail-closed).
7. 기존 watchdog 상향·재시작 로직 전체 무손상.

# 한국투자증권(KIS) Open API — 실매매 전 반드시 알아야/대비해야 할 것 (정독 정리)

> 2026-07-10. **KIS Open Trading API 공식 샘플(`koreainvestment/open-trading-api`) 소스
> 전수 + 개발자센터·python-kis 교차확인** 결과를 실운영 관점으로 정리. 목적: 브로커를
> 토스→KIS로 바꿀 때 "이건 몰라서 사고난다"를 없앤다.
>
> **이 문서는 `docs/TOSS_API_READINESS.md`의 KIS 판(版)이다.** 브로커 무관 계층(전략·주문
> 원장·UNKNOWN 대사·포지션 정체성·시드 격리·파수꾼)은 그대로 두고 **어댑터만 교체**하는
> 게 전제. 토스와 **결정적으로 다른 3가지**를 먼저 못박는다:
> 1. **미국주 서버측 조건/스톱주문 = 없음.** 토스의 0차 방어(B0 조건주문)가 **KIS 미국주엔
>    존재하지 않는다.** 파수꾼이 1차이자 최후 방어선이 된다(§7).
> 2. **클라이언트 멱등키 = 없음.** 토스 `clientOrderId`(10분 창)조차 KIS엔 없다. 중복주문
>    방지는 100% 우리 원장 + 조회 대사 책임(§5·§6).
> 3. **개인계좌는 IP allowlist 불필요 + 진짜 모의투자(paper) 환경 존재.** 토스의 최대
>    골칫거리 둘(IP 403·모의 부재)이 KIS에선 사라진다(§1·§14). 이건 **큰 이득**.
>
> **표기**: [확정]=공식 샘플 소스에서 직접 확인 · [대조필요]=개발자센터 원문·실측으로 최종
> 확인(포털이 JS 렌더라 자동수집 실패한 항목 다수) · ✅=우리 시스템에 이미(브로커 무관으로)
> 반영 · ⬜=미구현/KIS 어댑터에서 신규.
>
> 출처는 맨 끝. 1차 출처는 공식 레포 `examples_user/kis_auth.py`·`overseas_stock/*`·
> `legacy/postman/모의계좌_POSTMAN_샘플코드_v1.6.json`(원문 코드에서 직접 확인).

## 1. 인증·토큰·보안 [확정]

| 항목 | 내용 | 대응 |
|---|---|---|
| 발급 | `POST /oauth2/tokenP` (**JSON** body: `grant_type=client_credentials`, `appkey`, `appsecret`) | ⬜ `bot/kis.py` 신규 (토스는 form, KIS는 JSON — 주의) |
| 만료 | `access_token` 유효 **24시간(86400초)**. `expires_in`(초) + `access_token_token_expired`(만료일시 문자열) 반환 | ⬜ 만료 임박 시에만 갱신 |
| **재발급 6h 창** | 발급 후 **6시간 이내 재요청 시 "동일 토큰" 반환**(신규 아님). 24h 만료 전 재사용이 정석 | ⬜ 파일/공유 캐시 필수 |
| **발급 레이트리밋** | **토큰 재발급 1분당 1회.** 과다발급 시 이용 제한(차단). 공식 권고="하루 1회 발급 후 캐시 재사용" | ⬜ **단일 token_manager + 발급 직렬화(락)** 필수 |
| 헤더 | `authorization: Bearer {token}` · `appkey` · `appsecret` · `tr_id`(거래ID·필수) · `custtype`(P 개인/B 법인) · `content-type: application/json; charset=utf-8` | ⬜ 헤더 빌더 |
| **hashkey** | `POST /uapi/hashkey`로 발급 · **주문 시 현재 필수 아님**(공식 주석: "생략 가능") | ⬜ 옵션으로만 구현(정책 변경 대비) |
| **IP allowlist** | **개인(custtype P): 불필요.** appkey/secret+토큰만으로 호출. (법인 B만 서버 IP 등록 필수) | ✅ **토스 대비 최대 이점** — VPS egress IP 변경·403 걱정 소멸 |
| WS 승인키 | `POST /oauth2/Approval` (body에 `appkey`+**`secretkey`** — REST의 `appsecret`과 필드명 다름!) → `approval_key` | ⬜ 실시간 붙일 때만 |

→ **토큰 동시성 함정 [확정]**: 6h 내엔 동일 토큰이라 무효화가 잘 안 드러나지만, **다중
프로세스가 각자 발급하면 "1분 1회" 제한에 걸려 차단**된다. 루프A/B/C가 각자 토큰을 따면
안 됨 → **단일 공유 토큰 캐시 + 발급 락**(토스 §15.1과 동일 철칙, KIS는 1분 제한 때문에 더
치명적). [대조필요] 발급주기 경과 후 신규 토큰이 직전 토큰을 무효화하는지는 apiportal 재확인.

→ **실전/모의 키 분리 [확정]**: 실전·모의는 **appkey/appsecret이 서로 다르다.** 같은 키로
다른 도메인 호출 불가(토큰 발급 서버와 호출 서버는 쌍으로 일치). 어댑터는 `(env, appkey,
appsecret, base_url, account)`를 **한 세트로 묶어** 관리.

## 2. Rate Limit — **계좌 단위 초당 버킷** (토스와 구조 다름) [확정 수치 / 단위 대조필요]

토스는 엔드포인트 그룹별 독립 버킷이었으나, **KIS는 초당(per-second) 단일 카운트**다.

| 환경 | 한도 | 근거 |
|---|---|---|
| 실전(prod) | **초당 20건** (계좌 단위) | python-kis `REAL_API_REQUEST_PER_SECOND=20`, 공식 README |
| 모의(vps) | **초당 2건** (계좌 단위) | python-kis `VIRTUAL_API_REQUEST_PER_SECOND=2` |
| 토큰 발급 | 1분당 1회 | §1 |
| WebSocket | 세션당 등록 ~40~41건(시세+호가+체결통보 합산) | python-kis 기본 40 |

→ **초과 응답 [확정]**: `rt_cd="1"`(실패) + **`msg_cd="EGW00201"`** + `msg1="초당 거래건수를
초과하였습니다."` 공식 백테스터는 이 코드에 **61초 대기 후 3회 재시도**. 슬라이딩 윈도우라
토큰버킷만으론 완전 회피 불가 → **재시도 백오프 필수**.
→ ⚠️ **모의 2건/초는 빡빡하다**: 보유 종목 준실시간 폴링(10~20초)·다종목 스캔이 모의에서
한도에 쉽게 닿음. **모의 테스트는 유량을 낮춰 설계**하고, 준실시간 시세는 실전키/외부피드로
분리(§14). [대조필요] 한도 단위(앱키 vs 계좌), 분당 제한 유무, 2026-03-20 신규고객 호출제한
공지의 실제 영향.

## 3. 시세 조회 [확정 존재 / 모의 제약 확정]

| 용도 | 엔드포인트(해외) | 모의 지원 |
|---|---|---|
| 현재체결가 | `/uapi/overseas-price/v1/quotations/price` | ⭕ |
| 기간별시세(일·주·월·년) | `.../inquire-daily-chartprice` 등 | ⭕ |
| **분봉(intraday)** | 해외주식분봉조회 | **✗ 모의 미지원** |
| **10호가·현재가상세** | 해외 현재가 10호가/상세 | **✗ 모의 미지원** |
| 실시간(WS) 지연호가/체결 | `HDFSASP0/1`·`HDFSCNT0` | [대조필요] 모의 송출 여부 미확정 |

→ **핵심 함정 [확정]**: **모의에선 분봉·10호가·현재가상세가 안 나온다.** 인트라데이 캔들을
KIS에서 뽑는 설계면 모의에서 공백. **시세 소스와 주문 소스를 분리** — 시세는 실전키 또는
외부 피드(현행 FDR 등), 모의는 **주문·체결·잔고 대사 검증 전용**으로 한정. [대조필요]
해외 실시간 웹소켓 시세의 모의 송출 여부(공식 명문 없음).

## 4. 계좌·자산·매수여력 [확정]

**계좌 체계 [확정]**: `CANO`(종합계좌 앞 8자리) + `ACNT_PRDT_CD`(상품코드 뒤 2자리, 주식=
**`01`**). **헤더가 아니라 요청 파라미터**(조회=query, 주문=body)로 매 호출 전달. 인증정보
(appkey/secret/token/tr_id/custtype)만 헤더.

**★ appkey ↔ 계좌 카디널리티 (시드 격리의 핵심) [확정]**:
- **1 appkey/appsecret = 1 계좌.** 여러 계좌는 계좌마다 별도 키 발급.
- 발급 한도: **실전 최대 89계좌 / 모의 최대 2계좌.**
- → **봇 전용 계좌에 별도 appkey를 물리면 시드 격리(07 파일 IS1-A "별도 계좌")가 자연 성립**.
  토스는 "봇 전용 2번째 계좌 개설 가능?"이 미확정이라 논리 격리로 후퇴했는데, **KIS는 계좌
  단위 발급이 기본이라 물리 격리가 정공법**. (모의 2계좌 한도 안에서 봇 계좌 1개 확보.)

| 용도 | URL(해외/미국) | tr_id 실전/모의 | 모의 |
|---|---|---|---|
| 해외잔고(종목별·예수금) | `/uapi/overseas-stock/v1/trading/inquire-balance` | `TTTS3012R`/`VTTS3012R` | ⭕ |
| 체결기준현재잔고(통합 뷰·외화예수금) | `.../inquire-present-balance` | `CTRP6504R`/`VTRP6504R` | ⭕ |
| **해외 매수가능금액** | `.../inquire-psamount` | `TTTS3007R`/`VTTS3007R` | **✗ 모의 미지원** |
| 외화잔고/증거금(통합증거금값) | `.../foreign-margin` | `TTTC2101R` | [대조필요] |

→ **매도가능수량(해외)**: 별도 API 없음. **inquire-balance output1의 `ord_psbl_qty`(주문가능
수량)/`ovrs_cblc_qty`(잔고수량)로 판단** [확정]. (국내는 `inquire-psbl-sell` 별도 존재.)
→ **매수여력 함정 [확정]**: `inquire-psamount`(매수가능금액)가 **모의 미지원**. 주문 전
매수여력 0차 검증을 KIS 응답에 의존하면 **모의에서 계약이 깨진다.** → 매수여력은 **잔고 기반
클라이언트 계산으로 대체**하거나 env별 분기(실전만 API). 핵심 필드: `ord_psbl_frcr_amt`(주문
가능외화), `echm_af_ord_psbl_amt`(환전이후 주문가능=통합증거금 반영), `itgr_ord_psbl_amt`
(foreign-margin의 통합주문가능금액=최종 매수여력).
→ 거래소·통화별 호출 [확정]: 해외 inquire-balance는 `OVRS_EXCG_CD`(NASD/NYSE/AMEX)+
`TR_CRCY_CD`(USD) **필수** — 미국 전체 보유를 보려면 세 거래소를 각각, 또는 통합 뷰는
inquire-present-balance(`NATN_CD=840`).

## 5. 주문 생성 (해외/미국) `POST /uapi/overseas-stock/v1/trading/order` [확정]

**요청 body 핵심**:
| 필드 | 값 | 주의 |
|---|---|---|
| `CANO`·`ACNT_PRDT_CD` | 계좌 8-2 | body에 |
| `OVRS_EXCG_CD` | `NASD`/`NYSE`/`AMEX` | 통화(USD)는 거래소코드로 결정 |
| `PDNO` | 티커(예 `AAPL`) | |
| `ORD_QTY` | 정수 문자열 | 소수점 주문은 [대조필요](표준 OpenAPI는 정수 전제) |
| `OVRS_ORD_UNPR` | 주문단가 · **시장가/취소 시 `"0"`** | |
| `ORD_DVSN` | `00`지정가 · `31`MOO · `32`LOO · `33`MOC · `34`LOC | **연속장 즉시 시장가 코드 없음**(아래) |
| `SLL_TYPE` | 매도 `"00"`, 매수 공란 | |
| `ORD_SVR_DVSN_CD` | `"0"` 고정 | |
| `MGCO_APTM_ODNO` | 운용사지정주문번호 | 유일한 클라 지정 필드 — **멱등 보증 없음**(§6) |

→ **★ 매수/매도는 `tr_id`로 결정**(body에 매매구분 필드 없음): 미국 매수 `TTTT1002U` / 매도
`TTTT1006U`. **정정·취소** `order-rvsecncl` `TTTT1004U`(`RVSE_CNCL_DVSN_CD`=01 정정/02 취소,
`ORGN_ODNO`=원주문번호 필수). [확정]
→ **★★ 실전→모의 TR 매핑이 미국 매도에서 비대칭 [확정]**: 매수는 `TTTT1002U→VTTT1002U`
(T→V)지만 **매도는 `TTTT1006U→VTTT1001U`**(숫자까지 바뀜). 공식 예제의 기계적 `"V"+tr_id[1:]`
치환은 `VTTT1006U`를 만들어 문서값과 상충. → 어댑터는 **접두 스왑 금지, `(env×시장×매수매도)`
명시 매핑 테이블** 사용. [대조필요] 모의서버가 `VTTT1006U`도 받는지.
→ **★★★ ORD_DVSN에 스톱·연속장 시장가 없음 [확정]**: 미국 매수는 `00/32/34`만(시장가 없음),
매도는 `31`(MOO)·`33`(MOC)이 있으나 **장개시/장마감 단일가 전용** — **연속장 중 즉시 시장가
불가**. 급락 손절은 **마켓터블 지정가**(현재가에 슬리피지 버퍼 준 aggressive `ORD_DVSN=00`)로
구현 + 미체결/부분체결 chase 로직 필요. "손절=시장가 즉시체결" 가정을 버려야 함(§7).

**응답 output [확정]**: `KRX_FWDG_ORD_ORGNO`(주문조직번호) · `ODNO`(**서버 채번 주문번호**) ·
`ORD_TMD`(HHMMSS). 정정·취소도 새 ODNO 발번. → **정정/취소·대사에 ODNO 필수 → 원장에 저장.**

## 6. 멱등·UNKNOWN 대사 — **KIS엔 클라 멱등키가 없다** [확정 — 가장 중요]

> 토스는 `clientOrderId`(10분 창)라도 있었다. **KIS엔 클라이언트 지정 멱등키 자체가 없다.**
> 중복주문 방지·UNKNOWN 복구는 **전적으로 우리 원장 + 조회 대사**가 짊어진다.

- **ODNO는 서버가 응답으로 부여** → 사전 멱등키로 못 씀. 타임아웃으로 응답을 잃으면 **ODNO
  자체를 못 받는다** → 그대로 재주문하면 **중복체결**.
- `MGCO_APTM_ODNO`(운용사지정주문번호)가 유일하게 클라가 값 넣는 자리지만: (a) 주문 지목 키로
  안 쓰임, (b) **조회 응답에 에코 안 됨**(python-kis 매핑에 필드 없음), (c) 서버 중복거부 보증
  **미확인** → **멱등키로 신뢰 금지**. [대조필요] 조회 output에 실제 포함되는지 apiportal 원문.
- **대사 채널 2개 [확정]**:
  - 미체결내역 `inquire-nccs` `TTTS3018R` — 계좌+거래소로 리스트(ODNO 필터 없음).
  - 주문체결내역 `inquire-ccnl` `TTTS3035R`/`VTTS3035R` — **"ODNO로 검색 불가, 반드시 Null"**
    명시. 계좌+기간+종목+매도매수+체결구분으로 조회 후 **클라이언트가 필터**.
  - 완전체결은 미체결에 안 뜨므로 **두 조회 모두** 태워야 특정 가능.
- **어댑터 계약 [확정 함의]**: (1) 타임아웃=재주문 금지, 조회 우선. (2) **자체 합성 대사키**
  `(계좌, ovrs_excg_cd, pdno, 매도매수, 반올림 수량·단가, ord_tmd±윈도우)`로 리스트 대조. 미국주
  소수 체결단가(`ft_ccld_unpr3`)·환율 주의. (3) 포지션 정체성 멱등키는 **우리 원장이 소유**,
  ODNO는 취소/정정용 "서버 핸들". → ✅ `bot/ledger.py` UNKNOWN 잠금·대사 골격 **그대로 재사용**
  (오히려 KIS의 이 공백을 메우라고 만든 구조).

**공통 응답/에러 [확정]**: `rt_cd`(**"0"=성공**, 그 외 실패) · `msg_cd` · `msg1`(한글).
`EGW####`=게이트웨이(`EGW00201` 유량초과·`EGW00356` TR_ID 첫글자 오류), `MCA####`=업무오류
(`MCA05918` 종목코드 오류). ✅ `classify_error()`를 KIS `rt_cd/msg_cd` 기준으로 재작성(⬜).
[대조필요] EGW00201의 HTTP status(200 바디 vs 5xx), 전체 코드표(포털 `/faq-error-code` JS렌더).

## 7. 손절 방어 = **파수꾼이 1차이자 최후** (토스 대비 강등) [확정]

> **토스 검토의 최대 교정이 "OCO=보조 방어 강등"이었다. KIS 미국주는 그보다 더 나쁘다 —
> 서버측 조건/스톱주문이 아예 없다.** 0차 방어(B0) 계층이 통째로 사라진다.

| 시장 | 서버측 스톱 | 근거 |
|---|---|---|
| **미국(해외)** | **없음** | 해외 주문 body에 `CNDT_PRIC`·트리거 필드 부재. ORD_DVSN에 스톱 코드 없음 [확정] |
| 국내 | 스톱지정가 있음 | `order-cash` `ORD_DVSN=22`+`CNDT_PRIC`(트리거 후 **지정가** 발주, 시장가 아님). KRX·NXT만, 모의는 KRX만 [확정] |
| OCO/브래킷 | **KIS 전체 없음** | 국내·해외 모두 네이티브 미지원 → 어댑터가 2-leg+폴링 reconcile로 에뮬레이트 [확정] |

→ **설계 직격 [확정]**: 유니버스 95%가 미국주 → **0차 방어를 KIS에 위임 불가**. 파수꾼(watchdog)
손절이 **1차이자 최후 방어선**. ⇒ **파수꾼 생존성 = 손절 신뢰성.** 상시 호스트·하트비트
dead-man·워치독 재기동·프로세스 격리를 **토스 때보다 더 강하게** 가져가야 함(04 파일 I2/I5,
06 파일 SLA를 상향).
→ **손절 주문 형태 [확정]**: 연속장 시장가 없음 → **마켓터블 지정가 + chase + 슬리피지 상한**을
원장에 반영. 진짜 시장가는 MOO(31)/MOC(33) 즉 장개시·장마감 단일가뿐(인트라데이 급락엔 부적합).
→ **예약주문은 스톱이 아님 [확정]**: 해외 `order-resv`(`TTTT3014U`/`TTTT3016U`)는 **시간 예약**
(가격 트리거 아님), 미국은 정정 없음(취소 후 재접수), 당일 유효·장마감 자동취소, **모의 예약주문
조회 미지원**. 손절 대체 불가.
→ 참고: 국내 스톱지정가(ORD_DVSN=22)는 있으나 우리 유니버스엔 거의 무의미. `supports_server_side
_stop` 플래그를 **시장별 분기**(국내 true·미국 false)로 어댑터에 둔다.

## 8. WebSocket 체결통보 — 대사 1차 채널 후보 [확정]

- 해외 체결통보 TR: **`H0GSCNI0`(실전) / `H0GSCNI9`(모의)**. `approval_key`로 구독, HTS ID 필요,
  등록 1건.
- **접수·체결 모두 푸시** [확정]: `CNTG_YN`==`2`→체결통보, `1`→주문·정정·취소·거부 접수통보.
  `RFUS_YN`(거부), `ACPT_YN`(접수/확인/취소).
- **AES256-CBC 암호화** [확정]: 구독 응답 `key`/`iv`로 복호화 후 `^` split 파싱.
- **대사 활용 [확정]**: 통보의 `ODER_NO`가 주문응답 `ODNO`와 매칭 → **UNKNOWN 대사·포지션
  정체성 키로 직결.** 체결통보 WS를 원장 대사 1차 채널로 쓰면 폴링 부하↓. ⬜ 실주문 단계.
- 함정 [확정]: 통보 종류(접수 vs 체결)에 따라 필드 의미가 이동(주문수량이 `CNTG_QTY`↔`ODER_QTY`
  자리 이동), 미국 체결단가 소수점 위치 통화별 상이.

## 9. 통합증거금 = 원화로 미국주 매수(자동환전) [확정 존재 / 정책 대조필요]

- KIS "해외주식 통합증거금": 사전 환전 없이 **원화(및 국내주식 매도예정금)를 매수증거금으로**
  미국주 매수 → 정해진 자동환전일에 결제 외화만큼 자동 환전. **옵트인(별도 신청) 서비스** [확정].
- **의미**: 토스 설계의 **X3(환전 처리) 단계를 사실상 제거** — 원화 시드로 바로 미국주 매수.
  API 반영 지점: `inquire-psamount.echm_af_ord_psbl_amt`(환전이후 주문가능), `foreign-margin.
  itgr_ord_psbl_amt`(통합주문가능금액).
- ⚠️ **[대조필요/원칙 확인]**: 통합증거금이 **미수/신용(빚)** 성격인지 확인 — 우리 원칙은
  현금(cash-only). "원화로 매수 후 자동환전"이 신용공여가 아니라 **보유 원화 범위 내 결제**인지
  모의에서 검증. 미신청 계좌는 사전 환전(외화예수금)으로만 매수 → **어댑터가 계좌 설정에 따라
  분기**. [대조필요] 미신청 계좌의 원화주문 거부 에러코드, 자동환전 시점·환율, 신청상태 API 판별.

## 12. 실주문(Stage 2) 전 반드시 실측/확정할 것

1. **모의 미국 매도 TR_ID** 실제 수용값(`VTTT1001U` 확정 vs 예제산출 `VTTT1006U` 상충).
2. **UNKNOWN 대사 실측** — 타임아웃 후 nccs+ccnl 조회로 당일 주문을 휴리스틱으로 특정 가능한가
   (안 되면 Stage 2 No-Go). `MGCO_APTM_ODNO`가 조회에 에코되면 대사 신뢰도 급상승 → 실측.
3. **통합증거금** — 미수/신용 아님 확인 + 원화 매수 후 자동환전 시점·환율·미신청 거부 코드.
4. **파수꾼 마켓터블 지정가 손절** — 슬리피지 버퍼·chase·부분체결 잔여 처리 실측(연속장 시장가
   부재 전제).
5. **모의→실전 능력차** — 매수여력·예약조회·분봉·주간거래 모의 미지원을 회귀 트랙에서 커버.
6. **레이트리밋 실단위** — 20/s·2/s가 앱키 vs 계좌 단위인지, 분당 제한 유무, EGW00201 HTTP status.
7. **토큰 무효화** — 발급주기 경과 후 신규 토큰이 직전을 무효화하는지(다중프로세스 안전성).
8. **소수점 주문** — OpenAPI 주문 엔드포인트가 소수 수량을 받는지(안 되면 whole-share 강제 유지).
9. **체결통보 WS** — 모의 해외 실시간 시세·체결통보(`H0GSCNI9`) 실제 송출·복호화 파싱.
10. **앱 수동주문 ↔ API 주문 병존** — 봇 전용 계좌면 원천 차단(IS1-A), 그래도 holdings 재조회 대사.
11. **주문체결내역 조회로 완전체결분 회수** — 미체결에 안 뜨는 완결 주문을 ccnl로 특정.
12. **전체 에러코드표** — 개발자센터 `/faq-error-code` 원문(JS 렌더라 미수집).

## 13. 아키텍처 원칙·Go/No-Go (토스 §15에서 KIS로 이월)

### 13.1 철칙 (그대로 유효)
- **GitHub Actions·CF Worker엔 "주문 가능" KIS 키(실전 appsecret)를 절대 두지 않는다.** 신호·
  발사·검증·렌더만. 주문 키는 **상시 서버에만**. (KIS 개인계좌는 IP allowlist가 없어 서버 IP
  고정 부담은 없지만, **키 격리 원칙은 동일**.)
- **환경 분리 플래그**: `KIS_ENV=mock|live` · `LIVE_TRADING_ENABLED` · `ALLOW_BUY` · `ALLOW_SELL`
  · `LIVE_CANO`/`LIVE_ACNT_PRDT_CD` · `MAX_LIVE_RISK_PCT`. Stage 0/1엔 주문 키·플래그 미부여.
- **단일 token_manager**(1분 제한 때문에 KIS는 필수 강도↑) + 초당 rate limiter. NTP 시계오차>2초 주문 금지.

### 13.2 Stage 2 No-Go (하나라도 남으면 실주문 금지)
UNKNOWN 대사(nccs+ccnl 휴리스틱) 실측 미완 · 미국 매도 TR 비대칭 미검증 · 파수꾼 마켓터블
지정가 손절 미검증 · 통합증거금 신용성격 미확인 · **깃에 주문 가능 실전 키 존재** · 모의에서만
검증하고 실전 능력차(시장가·매수여력) 무시 · 보호(파수꾼) 생존성 SLA 없음 · 소수점 주문 가능여부 모름.

### 13.3 Stage 2 첫 주 제한
봇 전용 계좌(별도 appkey)만 · 한 시장(US)만 · **whole share만** · 동시 1종목 · 하루 신규 1건 ·
risk ≤0.1% · 마켓터블 지정가 손절만 · 앱 수동주문 금지 · 파수꾼 하트비트 정상일 때만 진입.

## 14. 토스 대비 KIS 순득실 요약

| 축 | 토스 | KIS | 판정 |
|---|---|---|---|
| IP allowlist | 강제(403·VPS IP 골칫거리) | **개인 불필요** | **KIS 우위(큰 이득)** |
| 모의투자 | 없음 | **있음**(주문·대사 검증) | **KIS 우위(큰 이득)** |
| 서버측 조건/스톱(0차 방어) | 있음(보조 강등) | **미국 없음** | **토스 우위(파수꾼 부담↑)** |
| 클라 멱등키 | clientOrderId(10분) | **없음** | 토스 우위(우리 원장이 커버) |
| 연속장 시장가 | 있음 | **없음**(마켓터블 지정가) | 토스 우위(손절 형태 변경) |
| 계좌 격리 | 2번째 계좌 미확정 | **1키=1계좌**(물리 격리 자연) | **KIS 우위** |
| 원화 미국주 매수 | 환전 별도(X3) | **통합증거금(자동환전)** | KIS 우위(신용성격 확인 조건) |
| 레이트리밋 | 그룹 독립 버킷 | 초당(모의 2/s 빡빡) | 소폭 토스 우위 |

→ **총평**: **IP·모의·계좌격리에서 KIS가 확실히 낫고, 손절 방어(서버측 조건주문·연속장 시장가)
에서 토스가 낫다.** 우리 아키텍처는 이미 "파수꾼 중심 손절 + 원장 소유 멱등"이라 KIS의 약점을
**설계상 이미 흡수**하고 있고(0차 방어는 원래 보조로 강등돼 있었음), IP·모의·격리 이득이 커서
**KIS 전환은 순득**. 단 파수꾼 생존성·마켓터블 지정가 손절을 상향하는 게 조건.

# KIS 모의투자 vs 실전매매 — 차이 명세서 (자동매매 관점)

> 2026-07-10. **"모의에서 잘 됐는데 실전에서 다르면 안 된다"**는 우려에 답하는 문서.
> 공식 `koreainvestment/open-trading-api`의 **모의 지원 매트릭스(`legacy/postman/README.md`)**
> + 예제 코드 주석에서 **직접 확인**한 사실 기준. 다중에이전트 검증(3-vote) 통과분.
>
> **핵심 결론 한 줄**: 모의는 **실전의 부분집합**이다. **주문·체결·잔고·대사 로직은 모의로
> 믿을 수 있지만**, 하필 우리 방어 설계의 일부(**시장가 손절·매수여력 프리체크·인트라데이
> 시세·주간거래**)가 **모의에 없다** → 이 항목들은 **실전 소액에서 처음 검증**된다. 그 목록을
> 아래 C·D에 못박았다.
>
> **표기**: [확정]=공식 매트릭스/코드 직접 확인 · [대조필요]=실측 필요.

---

## A. 완전히 동일 — 모의로 검증하면 실전에서도 믿는다 [확정]

이 계약들은 모의·실전이 **같은 엔드포인트·같은 필드·같은 응답 구조**다. 모의에서 통과하면
실전에서도 동일하게 동작한다(도메인·키·TR 접두만 바뀜, §B).

| 기능 | 엔드포인트 | 왜 믿어도 되나 |
|---|---|---|
| **해외 주문(매수/매도)** | `.../overseas-stock/v1/trading/order` | 모의·실전 둘 다 ⭕. 요청 필드·응답(`ODNO` 등) 동일 |
| **정정/취소** | `.../order-rvsecncl` | 둘 다 ⭕. `ORGN_ODNO` 계약 동일 |
| **미체결내역** | `.../inquire-nccs` | 둘 다 ⭕. UNKNOWN 대사 채널 A |
| **주문체결내역** | `.../inquire-ccnl` | 둘 다 ⭕. 대사 채널 B (ODNO 검색불가·클라 필터도 동일) |
| **해외잔고** | `.../inquire-balance` | 둘 다 ⭕. 보유·매도가능수량(`ord_psbl_qty`) 동일 |
| **체결기준현재잔고** | `.../inquire-present-balance` | 둘 다 ⭕ |
| **현재체결가** | `.../overseas-price/.../price` | 둘 다 ⭕(단일 조회) |
| **기간별시세(일·주·월·년)** | `.../inquire-daily-chartprice` | 둘 다 ⭕ |
| **예약주문 접수** | `.../order-resv` | 둘 다 ⭕ (단 **조회**는 모의 ✗, §C) |

→ **의미**: 우리 설계의 **뼈대(주문 원장·멱등·UNKNOWN 대사·포지션 정체성·잔고 대사)는 모의
에서 그대로 검증된다.** 이게 KIS 모의를 쓰는 진짜 이유. 여기까지는 "모의 green = 실전 green".

## B. 코드만 다름 — 로직은 같고, 어댑터가 자동 전환 [확정]

값만 바뀌지 **행위는 동일**. 어댑터의 `KIS_ENV=mock|live` 한 스위치로 전부 전환.

| 항목 | 모의(vps) | 실전(prod) |
|---|---|---|
| REST 도메인 | `openapivts.koreainvestment.com:29443` | `openapi.koreainvestment.com:9443` |
| WS 도메인 | `ops.koreainvestment.com:31000` | `:21000` |
| appkey/appsecret | 모의 전용 | 실전 전용 (**서로 못 섞음**) |
| 계좌번호(CANO) | 모의 전용 | 실전 전용 |
| TR_ID 접두 | `V…` | `T…` |
| 체결통보 WS TR | `H0GSCNI9` | `H0GSCNI0` |

→ ⚠️ **단 하나의 함정 [확정]**: **미국 매도 주문 TR만 비대칭** — 실전 `TTTT1006U` ↔ 모의
`VTTT1001U`(숫자까지 다름). 나머지는 전부 `T↔V` 접두 치환이지만 **여기만 예외**. 어댑터에
`"V"+tr_id[1:]` 기계치환 대신 **명시 매핑 테이블**을 박아 이 하나를 못 틀리게 한다. (매수·
정정취소·조회는 접두 치환 안전.) 우리 어댑터가 처리하므로 **네가 신경 쓸 필요는 없음** —
다만 "모의에서 매도 잘 됐는데 실전 매도가 TR 틀려서 거부"가 이론상 유일한 위험점이라 명시.

## C. ★ 모의에 아예 없음 — 실전 첫날 처음 겪는 것 (위험구간) [확정]

**여기가 "모의 잘돼서 했는데 실전서 다른" 바로 그 지점이다.** 모의에선 호출 자체가 안 되므로
**실전 소액 단계에서만 처음 검증**된다. 우리 회귀 계획은 이걸 별도 트랙으로 격리한다.

| 모의 미지원 기능 | 우리 설계 영향 | 실전서 처음 검증할 것 |
|---|---|---|
| **매수가능금액조회**(`inquire-psamount`) | 매수 전 매수여력 0차 검증 | 실전선 API로, 모의선 **잔고 계산으로 대체** — 두 경로가 같은 수량을 내는지 |
| **미국 주문유형 시장가류**(MOO/MOC/LOO/LOC) — 모의는 **`00` 지정가만** | **파수꾼 손절**을 모의선 지정가로만 검증 | 실전서 마켓터블 지정가 손절·부분체결·chase 실측 |
| **예약주문 조회**(접수는 ⭕, 조회 ✗) | 제출 후 read-back 대사 | 실전서 예약주문 상태 확인, 모의선 미체결내역으로 우회 |
| **미국 주간거래**(daytime-order/정정취소) | 주간세션 진입·손절 | 실전서만 존재 → 주간세션 로직 전체 |
| **해외주식 분봉조회 / 지수 분봉** | 인트라데이 캔들 | 모의선 못 뽑음 → **시세는 실전키/외부피드로 분리** |
| **현재가 10호가 / 현재가상세** | 호가공백·슬리피지 판단 | 실전서 호가 기반 손절 판단 |
| **기간손익 / 일별거래내역 / 결제기준잔고 / 해외증거금 통화별** | 정산·세금·증거금 회계 | 실전서 정산 회계 |

→ **행동수칙**: 모의 통과를 "전 경로 검증"으로 **착각 금지**. 위 7항목은 **Stage 2 실전 소액에서
반드시 재검증**한다는 걸 원장·런북에 명시(`KIS_API_READINESS.md §10·§12`).

## D. 동작이 다를 수 있음 — 값은 나오지만 신뢰도 주의 [대조필요]

호출은 되지만 **모의의 결과가 실전과 다르게 나올 수 있는** 회색지대. 실측으로만 확정.

| 항목 | 우려 | 실측 방법 |
|---|---|---|
| **모의 체결 시뮬레이션** | 지정가 기준 체결이라지만 **체결 타이밍·가격·부분체결·미체결 처리**가 실전과 다를 수 있음. 모의는 실제 시장 유동성이 없어 "지정가 닿으면 체결" 같은 단순 규칙일 가능성 | 모의서 여러 지정가로 주문→체결/미체결 패턴 관찰, 실전 소액과 대조 |
| **모의 정규장 한정 여부** | 프리/애프터·주간 세션에서 모의 체결이 되는지 불명 | 세션별 주문 접수·체결 관찰 |
| **모의 해외 실시간 WS 시세** | :31000 도메인은 있으나 **해외 실시간 시세가 모의서 송출되는지 공식 명문 없음**(주문 시뮬용만일 가능성) | WS 구독 후 시세 수신 여부 |
| **모의 체결통보 WS**(`H0GSCNI9`) | 체결 푸시가 모의서 정상 오는지 | 모의 주문 후 통보 수신·복호화 |
| **통합증거금(원화 미국주 매수)** | 모의서 원화 매수 동작이 실전과 같은지, **미수/신용 성격 아닌지** | 모의 통합증거금 매수 관찰, 신용성격 확인 |
| **레이트리밋 체감** | 모의 **초당 2건**(실전 20건) → 모의선 유량 여유가 훨씬 빡빡 | 모의선 폴링 주기 낮춰 설계, 실전선 확장 |

## E. 둘 다 없음 — 모의·실전 공통 한계 (KIS 자체 특성) [확정]

모의/실전 차이가 아니라 **KIS라서 없는 것**(토스와 다른 점). 모의로도 실전으로도 안 되니
설계로 메운다.
- **미국주 서버측 조건/스톱/OCO 주문 없음** → 파수꾼이 최후 방어선(§READINESS §7).
- **연속장 즉시 시장가 없음** → 마켓터블 지정가 손절.
- **클라이언트 멱등키 없음** → 우리 원장 + nccs/ccnl 대사가 유일 방어.

## F. 결론 — 모의를 어디까지 믿나

```
믿어도 됨 (A·B):  주문 접수·정정·취소 / 체결·미체결·잔고 조회 / UNKNOWN 대사 /
                  포지션 정체성·멱등 원장 / 지정가 주문 흐름
                  → 모의 green이면 실전서도 이 로직은 동일하게 간다.

실전서 처음 (C):  시장가류 손절 / 매수여력 API / 예약주문 조회 / 주간거래 /
                  인트라데이 분봉·10호가 / 정산·세금 회계
                  → 모의 통과 ≠ 검증완료. 실전 소액에서 재검증.

실측 필요 (D):    모의 체결 시뮬 정확도 / 실시간 WS 시세·통보 / 통합증거금 성격 / 유량
                  → 값이 나와도 실전과 대조 전엔 신뢰 보류.

설계로 메움 (E):  서버측 스톱·시장가·멱등키 부재 → 파수꾼 + 마켓터블 지정가 + 원장 대사.
```

→ **한 줄 답**: "모의 잘돼서 했는데 실전서 다르면?" — **주문·대사 뼈대(A·B)는 안 다르다.
안심하고 모의로 검증하면 된다. 단 C의 7항목은 모의에 없어서 실전 소액에서 처음 겪으니,
"모의 통과 = 전부 검증"으로 착각만 안 하면 된다.** 그래서 Stage 2 첫 주를 봇 전용 계좌·1종목·
whole-share·하루 1건으로 좁혀 C를 안전하게 실측한다.

# KIS 전환 재계획 검토 요청 (Codex/GPT 리뷰어용)

## ⚠️ 읽는 법 (반드시 지켜라 — 컨텍스트 손실 방지)
문서가 길다. **절대 한 번에 다 읽고 총평하지 마라.**
1. 먼저 `docs/kis/KIS_API_READINESS.md`를 **`##` 섹션 하나씩** 연다. 각 섹션만 읽고 →
   그 섹션의 사실 주장(특히 [확정]/[대조필요] 표기)이 맞는지 판정 → 다음 섹션.
2. 그다음 `docs/kis/KIS_MIGRATION_FROM_TOSS.md`를 **`##` 하나씩** 읽으며 델타(바뀌는 것/
   그대로인 것)가 타당한지 판정.
3. 필요 시 토스 원설계(`docs/live_design/00~07`, `docs/TOSS_API_READINESS.md`)를 대조하되,
   **역시 태스크(`##`) 단위로만** 편다. 한 번에 여러 파일을 요약하지 마라.
4. 각 파일을 끝낼 때마다 **중간 요약(채택/수정/기각 목록)**을 내고 다음으로.
5. 모두 끝난 뒤에만 전체 종합 판정.

## 너의 역할
너는 **국내 증권 Open API(특히 KIS 한국투자증권)로 실계좌 자동매매를 운영**해 본 시니어
트레이딩 인프라 엔지니어다. 아부·요약 칭찬 금지. **"이 지점이 이 순서로 이렇게 깨진다"는
구체적 실패 시나리오**만 가치 있다. 우리가 이미 토스로 27태스크를 설계·리뷰했고 지금은
**브로커만 KIS로 바꾸는 델타**를 검토받는 상황임을 전제로 봐라.

## 배경 (핵심만)
- 차트 전략(52주 저점권 진입·ATR 손절·손익비 1:2·일봉 스윙·R배수 엑싯) → **KIS 실계좌**
  자동매매가 목표. 시드 1억(봇 몫은 고정 SEED 봉투로 제한), 종목당 1/3, 1% 리스크.
  유니버스 ~5,400(**95% 미국주**).
- 현재: GitHub Actions 무료 배치 + CF Worker + 매도전담 파수꾼(dry-run)으로 **가상 모의투자**.
  토스는 시세 읽기 전용 어댑터까지 구현했고, **이제 KIS로 전환**한다.
- **브로커 무관 골격(재작성 대상 아님)**: `bot/ledger.py`(주문 원장·UNKNOWN 잠금·대사·잔여),
  `bot/sentinel.py`(파수꾼·포지션 멱등키), 07 파일(시드 봉투·계좌격리 IS1~IS5), 04 파일
  (상시서버·kill-switch·롤아웃 가드), `bot/notify.py`(ntfy P0). **어댑터만 `bot/toss.py`→
  `bot/kis.py`로 교체.**
- **KIS가 토스와 결정적으로 다른 3가지**(이 검토의 핵심 축):
  1. **미국주 서버측 조건/스톱/OCO 주문 = 없음** → 0차 방어 계층 소멸, 파수꾼이 최후 방어선.
  2. **클라이언트 멱등키 = 없음**(토스 clientOrderId조차 없음) → 원장+조회 대사가 유일 방어.
  3. **개인계좌 IP allowlist 불필요 + 진짜 모의투자(paper) 존재** → 토스의 골칫거리 둘 소멸.

## 집요하게 볼 것 (KIS 특유의 함정)
1. **UNKNOWN·이중주문**: KIS는 클라 멱등키가 없고 `ODNO`는 서버 채번이라 타임아웃 시 유실.
   대사는 **nccs(미체결)+ccnl(체결내역) 둘 다** 조회 + **자체 합성 키**(`계좌·거래소·티커·
   매도매수·반올림 수량/단가·ord_tmd±윈도우`)로 리스트 대조하는 설계다. → **이 합성 대사가
   실전에서 오매칭/누락으로 깨지는 시나리오**를 구체적으로 지적하라. (완전체결이 미체결에
   안 뜨는 케이스, 동일 종목 다중 주문 같은 초·같은 수량, 소수 체결단가·환율 반올림 충돌 등.)
2. **손절 형태 변경**: 연속장 시장가 부재 → 파수꾼이 **마켓터블 지정가 + chase**로 손절.
   급락(gap-down)·호가공백·부분체결·chase 무한루프·슬리피지 상한에서 **미보호 구간**이
   생기는 지점을 짚어라. 서버측 스톱이 없으니 **파수꾼 프로세스/네트워크 다운 = 무방비**인데,
   이 생존성 SLA가 충분한가?
3. **TR_ID 매핑**: 미국 매도 실전 `TTTT1006U` ↔ 모의 `VTTT1001U`(비대칭). 접두 스왑 금지·명시
   테이블 설계가 맞나? 다른 비대칭/함정이 더 있나?
4. **모의↔실전 능력차**: 모의는 매수가능금액조회·예약주문조회·분봉·10호가·주간거래·시장가
   미지원. **모의에서 green인데 실전에서 처음 터지는** 항목(시장가 손절·매수여력 프리체크·
   인트라데이 시세)을 회귀 계획이 제대로 격리했나?
5. **토큰**: 발급 1분당 1회·6h 재사용·다중프로세스 동시발급 차단 위험. 단일 token_manager가
   루프A/B/C·재시작·크래시에서 정말 직렬화되나?
6. **통합증거금**: 원화로 미국주 매수(자동환전)가 **미수/신용(빚) 성격**이면 현금 원칙 위배.
   미신청 계좌 분기·자동환전 시점 리스크를 짚어라.
7. **시드 격리**: 1 appkey=1 계좌라 봇 전용 계좌+별도 키로 물리 격리(IS1-A)가 자연 성립한다는
   판단이 맞나? 그래도 남는 잔여위험(같은 appkey로 다른 상품계좌 접근, 사용자가 봇 계좌를 앱에서
   직접 거래)은?

## 각 섹션/태스크마다 판정할 것
`채택 / 수정채택 / 보류 / 기각` + 근거 + (수정·기각이면) 구체적 실패 시나리오와 대안.

## 전체 종합에서 반드시 답할 것
- **Q1. 사실 오류**: `KIS_API_READINESS.md`의 [확정] 중 실제와 다른 것, [대조필요]로 남겼지만
  실은 확정 가능한 것. (엔드포인트·TR_ID·필드명·유량·모의 지원 여부 등.)
- **Q2. 빠진 델타**: 토스→KIS 전환에서 이 재계획이 놓친 변경점(세금·양도소득·결제일 T+2·주간
  거래·기업행위·환율 스프레드·WS approval_key 수명·모의 계좌번호 발급 등).
- **Q3. 그대로 둔다고 한 것 중 실은 바꿔야 하는 것**: "브로커 무관"이라 재사용한다고 했지만
  KIS 특성상 수정이 필요한 골격(원장 상태값, 파수꾼 매도 경로, 사이징 분모 등).
- **Q4. 과설계/미룰 것**: 모의·소액 단계엔 불필요한데 지금 하려는 것(체결통보 WS, 국내 스톱지정가,
  OCO 에뮬레이션 등).
- **Q5. Stage 2 Go/No-Go 관문이 충분한가** — 특히 UNKNOWN 대사 실측·파수꾼 생존성·통합증거금
  신용성격. KIS 고유의 No-Go 조건이 더 있나?
- **Q6. 가장 위험한 델타 3개**와 그 이유(구체 시나리오).
- **Q7. 판단**: KIS 전환이 순득이라는 우리 결론(IP·모의·격리 이득 > 서버측 스톱·시장가 손실)이
  맞나? 반대 논거가 있으면 제시하라.

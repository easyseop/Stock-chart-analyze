## P1-1. §R0 미실측 — 모의 환경 동작 미증명 (병합 차단)

사용자 실측 제보: "KIS 모의투자 화면에서도 잔고가 끝까지 스크롤되지 않는다."
모의가 연속조회를 지원하지 않으면 2페이지 요청이 `msg_cd=90000000`류로 거절되고,
이 구현은 모의에서 **1페이지 초과 시 항상 None**을 반환한다 — 개선 전과 동일한
차단 상태이며, 추가 API 호출만 늘어난다. 즉 **오늘 우리가 돌리는 환경에서는
위험이 전혀 해소되지 않았을 수 있다.**

또한 지시서 §R0 분기 B가 요구한 **보상 통제(한도 근접 경보)** 가 없다.
현재 `/진단`은 NASD 29종목을 성공 조회했으므로 **1페이지 한도는 ≥29로 추정**되나
정확한 값을 모르며, 넘는 순간 예고 없이 자동매도가 상시 차단된다.

**요구(작업량 작음, 재구현 불필요)**:
1. Oracle에서 읽기 전용 2페이지 요청 실측 → 지원 여부·1페이지 한도 행수 확정,
   문서 §7 추기.
2. 미지원이면 페이지 루프를 live 전용으로 유지 + **거래소별 보유가 한도의 80%를
   넘으면 1회 경고**(`/진단`·텔레그램) 추가.
3. 확정된 한도 숫자를 문서화 — 모의 기간 보유 상한·시드 증액 논의의 근거값.

## P2-1. 완전성 마커의 신뢰 경계가 코드로 강제되지 않음

`kis_reconcile.trusted_response_rows()`는 응답 dict 안의 `_pagination_complete`를
완전성 증거로 채택하고, 그 값이 True면 15/100행 포화 fail-closed를 **면제**한다.
그런데 이 마커는 `_get_all_pages`가 **브로커 응답 사본(`dict(response)`) 위에**
찍는 구조라, 우리 코드가 찍은 것과 응답에 실려온 것을 구분할 수단이 없다.

검토자 프로브(재현):
```
15행 포화 + {"_pagination_complete": True, "_pagination_pages": 1} → 완전 인정(행 15)
동일 응답에서 마커만 제거          → 거부(None)   ← 기존 fail-closed
```
오늘 실제 호출 경로는 전부 내부 생성이라 **활성 결함은 아니다**(그래서 P1 아님).
그러나 이 마커가 그대로 부재 증명(R1)의 완전성 근거이므로, 잘린 15행이 "완전"이
되는 순간 **열린 SELL ACK가 거짓 종결**될 수 있다 — 방어 깊이를 잃은 상태다.

**최소 수정**: `_get(...)` 응답 수신 직후 `_pagination_*` 접두 키를 제거해
(마커는 오직 `_get_all_pages`만 찍도록) 신뢰 경계를 코드로 고정하고, "브로커
응답에 마커가 실려와도 무시된다"는 회귀 테스트 1개 추가.

## P3 (비차단)

1. **페이지 간 중복 행 미제거** — 프로브 실측: 같은 행이 두 페이지에 오면
   `all_rows.extend`로 2건이 그대로 누적된다. 다운스트림이 대부분 심볼 dict로
   접히므로 수량 이중계상은 없으나, `positions_detail`·행수 기반 카운트
   (ops 스냅샷·readiness 대조)가 부풀려진다(오탐 방향 = 안전). 주문번호/심볼
   기준 dedup 또는 최소한 중복 감지 로그 권장.
2. **행 키 혼용 여지** — `canonical_row_key`는 1페이지에서 고정하는데, 2페이지가
   다른 후보 키(`output` vs `output1`)를 쓰면 서로 다른 배열이 한 키로 합쳐진다.
   현실 가능성은 낮으나 "페이지 간 행 키 불일치 → 불신" 한 줄이면 닫힌다.

## 확인된 것들 (반례 15개 요지)

- 중도 실패(None·rt_cd≠0·행 형식 불신)·연속키 반복·키 없는 F/M·상한 도달은 전부
  **전체 None**, 부분 행 반환 0 (M2·M3 뮤테이션 + 테스트 2·3·4로 고정).
- 첫 요청에 낡은 컨텍스트가 실려 있으면 HTTP 전에 거부(초기 상태 오염 차단).
- 연속 요청 `tr_cont=N` 헤더 계약이 테스트로 고정(M1 KILLED).
- 소진된 병합은 컨텍스트·연속 헤더를 제거해 반환 → 기존 소비자 "키 있으면 불신"
  계약 그대로 통과(소비자 수정 없음).
- 각 페이지가 기존 `_LIMITER`를 통과 — 유량 우회 없음. 단일 페이지는 호출 1회로
  기존과 동일(회귀 없음).
- 소비자 불신 사유가 `ContextVar`로 스레드 격리되어 `unknown` 라벨이 사라짐.
  시크릿·심볼·계좌 미저장 확인.
- KR mock 미체결 폴백의 live 금지 계약 유지, 주문 POST·kill·사이징·세션 게이트
  변경 0 확인(diff 검사).

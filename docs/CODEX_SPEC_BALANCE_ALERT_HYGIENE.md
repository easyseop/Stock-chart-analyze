## 1. 문제 (반복 실측)

KIS mock 잔고 API가 간헐 플래핑할 때마다 파수꾼이 "🚨 KIS 잔고 조회 실패 —
마지막 정상 잔고 N초 전 스냅샷으로 감시만 계속…" critical 경보를 **캐시 만료
사이클마다** 보낸다.

- 8/7 22:47~23:0x 밤: 수 회
- 8/8 새벽: 수 회
- 8/11 15:01~15:23: **22분간 8회** (1~6분 간격)

같은 원인의 반복 경보가 진짜 신규 경보(체결·손절·kill)를 묻는다. 또한 실패
원인(레이트리밋인지 KIS 서버 불안정인지)이 어디에도 기록되지 않아 나흘째
추정만 하고 있다.

## 2. 요구사항

### H1. 동일 원인 경보 묶음 (파수꾼 잔고 실패 경보)

- 첫 실패 경보는 즉시(현행 유지).
- 이후 **같은 원인 계열이 지속되는 동안 30분(BALANCE_ALERT_SUPPRESS_S,
  기본 1800초)당 1회**로 억제. 억제 중 재발은 카운트만.
- 지속이 60분을 넘으면 1회 **격상 경보**("60분째 간헐 실패 — 누적 N회").
- **회복 시 1회 회복 알림**("잔고 조회 회복 — 실패 누적 N회 · 총 지속 M분").
  회복 알림에 누적 통계를 실어 사건 전체가 한 줄로 요약되게 한다.
- 래치는 **전송 성공 시에만** 갱신(V2 P2-2에서 확립한 계약과 동일).
  프로세스 재시작 후 중복 1회는 허용(단순성 우선), 영구 유실은 불허.

### H2. 실패 원인 기록

- 잔고 조회 실패 시 가능한 원인 신호를 카운터로 기록:
  HTTP 상태코드, `rt_cd`/`msg_cd`(있으면), 예외 타입(타임아웃/연결오류).
  기록 위치는 파수꾼 프로세스 내 카운터 + 주기 로그 라인(저널)이면 충분 —
  새 파일이 필요하면 0600·시크릿 금지.
- `/진단`에 한 줄 추가: `잔고 실패(24h): N회 · 최다 원인 <코드/타입>`.
- ops_status 스냅샷에 `balance_fail_24h: N` 숫자 필드 1개만 추가.
- **레이트리밋 판별이 목적**: KIS 레이트리밋 응답(EGW00201 등 초과 코드)이
  잡히면 그 자체를 별도 카운트해 "우리 부하 문제"를 확정할 수 있게 한다.

### H3. (부수) ops 발행 루프 보호 — 야간 침묵 해소

이틀 연속(8/6·8/7 밤~아침) ops ntfy 발행이 밤 23시경 멈췄다 아침에 재개된
실측이 있다. 추정: `ops_status.snapshot()`의 KIS 조회(4시장)가 야간 플래핑
중 재시도/백오프에 장시간 블로킹되어 텔레그램 루프 전체가 멈춤.

- snapshot()의 KIS 조회 구간에 **총 시간 예산(기본 60초)**을 두고, 초과 시
  해당 시장 값을 `None`(미확인)으로 표기하고 발행은 계속한다.
- 텔레그램 루프가 어떤 경우에도 10분 이상 발행을 거르지 않는 것이 목표.

### H4. 대사 알림 자가 판정 (2026-08-11 사용자 요청 추가)

배경: 8/11 밤 "✅ 체결 확정 LCII 4주"(23:25) 직후 "⚠️ 매수 거절 종결 LCII
4주"(23:27)가 떠 사용자가 모순으로 오인, 수동으로 /진단을 돌려 확인해야
했다(실제로는 오늘 체결 + 과거 방치 전표 청소로 정상). 알림이 스스로
"정상/오류"를 판정해 실어야 한다.

- **접수 시각 표기**: 거절 종결·체결 확정 알림에 해당 주문의 접수
  일시(MM/DD HH:MM)를 포함한다 — 오늘 것인지 과거 청소인지 한눈에
  구분되게. 원장 submitted_at 사용.
- **정합 자동 판정**: 대사 이벤트(체결 확정·거절 종결) 처리 직후 그 종목의
  브로커 잔고 vs 봇 장부 수량을 대조해 알림에 판정 한 줄을 덧붙인다:
  - 일치 → `✅ 정합(보유 N주 = 장부 N주)`
  - 불일치 → `🚨 불일치(보유 N vs 장부 M) — 수동 확인 필요` (critical)
  - 조회 불가 → `정합 미확인(잔고 조회 실패)` — **지어내지 않는다**
- **동시 사건 관계 설명**: 같은 심볼에서 5분 내 체결 확정과 거절 종결이
  둘 다 발생하면, 나중 알림에 자동으로 관계를 명시한다:
  `"오늘 HH:MM 체결분과 별개 — MM/DD 접수 과거 전표 정리"`.
- 판정용 잔고 조회는 기존 읽기 전용 경로 재사용, 실패해도 대사 자체는
  영향 없음(판정 줄만 미확인 표기).

## 3. 주의

- **경보 억제는 잔고 실패 경보에만** — 체결·손절·kill·모순 경보는 억제 대상
  아님. 카테고리를 정확히 한정할 것.
- 파수꾼의 fail-closed 매매 동작(스냅샷 감시·주문 직전 재조회 차단)은 한 줄도
  바꾸지 않는다 — 이 지시서는 알림·관측 계층만.
- 격상·회복 알림도 critical=True(트레이드온리 필터 통과).
- 24h 카운터는 프로세스 메모리로 충분(재시작 시 리셋 허용 — /진단에
  "프로세스 기동 후" 명시).

## 4. 테스트 (최소)

1. 연속 실패 10회 시뮬 → 경보 1회(즉시) + 30분 후 1회 + 60분 격상 1회.
2. 회복 → 회복 알림 1회(누적 N·지속 M 포함), 이후 재실패는 새 사건으로 처음부터.
3. 전송 실패 시 래치 미갱신 → 다음 사이클 재시도.
4. 원인 카운터: HTTP 500·타임아웃·레이트리밋 코드 각각 분리 집계, /진단 표기.
5. snapshot() 시간 예산: KIS 조회 90초 블로킹 주입 → 60초에 끊고 해당 시장
   None으로 발행 성공.
6. 기존 스위트(특히 test_sentinel·test_ops_status·test_kis_telegram) 무손상.

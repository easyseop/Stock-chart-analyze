# 미국 종목 수집을 하루 10개씩 늘리는 방안 검토

작성일: 2026-08-06
대상: `easyseop/Stock-chart-analyze`

## 결론

현재 미국 보통주 유니버스는 이미 사실상 전부 수집돼 있다. 따라서 기존 종목에
무작위로 10개를 더하는 작업은 필요하지 않다. 앞으로 새로 상장되어 공식 심볼
목록에 추가되는 **보통주만 하루 최대 10개씩 수집**하는 별도 증분 절차가 적절하다.
ETF·ETN·워런트·우선주·SPAC 등을 숫자를 채우기 위해 섞어서는 안 된다.

이 검토는 데이터 수집 범위에 관한 것이며 KIS 주문 한도·하루 신규매수 종목 수를
늘리는 승인이 아니다.

## 2026-08-06 실측

- `universe.csv`: 전체 5,416종목
  - 미국 보통주 5,113종목
  - 한국 종목 303종목
- 최근 성공한 GitHub Actions 캐시: 5,414종목, 134.42 MiB
- 아직 캐시가 없는 종목: 2종목
- 현재 `.github/workflows/daily.yml`의 `CHUNK=9999`는 마감 후 미수집 종목을
  사실상 전부 백필하도록 되어 있다.
- 미국 목록은 NASDAQ 공식 `nasdaqlisted.txt`와 `otherlisted.txt`에서 만들며,
  코드상 ETF·ETN·Fund·Trust·Warrant·Unit·Preferred·SPAC 등을 제외한다.

즉 “현재 종목 + 하루 10개”라는 목표를 기존 보통주 범위에서 해석하면 이미
5,113종목을 확보했으므로 추가할 재고가 거의 없다. 남은 2종목은 별도 신규 범주가
아니라 기존 백필 실패/미완료분으로, 다음 전체 실행에서 재시도하면 된다.

## 권장 구조

1. 매일 마감 후 NASDAQ 공식 심볼 목록을 읽되 기존 `universe.csv`를 교체하지 않고
   새 보통주 티커만 계산한다.
2. 새 티커가 있으면 하루 최대 10개만 가격 이력을 백필한다.
3. 수집과 매매 권위를 분리한다. 백필 성공만으로 즉시 매수 후보가 되지 않게 한다.
4. 최소 이력·유동성·시세 완전성 검사를 통과한 종목만 기존 스크리너에 합류시킨다.
5. 종목별 실패는 기록하고 다음 날 재시도하며, 기존 정상 캐시는 삭제하거나
   덮어쓰지 않는다.
6. 수집은 공개 가격 데이터만 사용하므로 KIS API 호출량과 주문 경로는 늘리지 않는다.

## 거래 후보 승격 권장 게이트

- 최소 252거래일의 유효 일봉
- 최근 봉의 OHLCV 유한값·양수·날짜 단조 증가
- 최근 60거래일 평균 거래대금의 운영 하한 충족
- NASDAQ/NYSE/AMEX 보통주이며 ETF·파생·우선주가 아님
- 전략 A/B가 요구하는 이동평균·손익비·손절폭 계산에 결측 없음
- 새 티커는 최초 1회 그림자 스캔에서 예외·비정상 신호가 없음을 확인

이 게이트는 “가격을 모아 본다”와 “KIS가 살 수 있다”를 분리한다. 추가 수집으로
후보 풀이 넓어져도 기존 신선도·세션·예산·손절·전략 계약·중복주문 게이트를
우회하지 않는다.

## 하지 말아야 할 변경

- 현재 `CHUNK=9999`를 단순히 `10`으로만 바꾸기: 캐시가 유실된 재해복구 때
  5천 종목 복구에 500일 이상 걸린다.
- 알파벳순으로 ETF·워런트·OTC를 매일 10개 추가하기: 전략 입력 분포가 달라지고
  저유동성·비정상 가격 위험이 커진다.
- 백필 완료 즉시 KIS 매수 허용하기: 수집 성공은 전략 적합성 증명이 아니다.
- Oracle의 매매 서비스에 대량 백필을 결합하기: 수집 지연/OOM이 sentinel·buyloop에
  영향을 줄 수 있다.

## 다음 구현안

현재는 이미 99.96%가 캐시돼 있으므로 즉시 대량 변경할 이유가 없다. 다음 신규상장
대응 작업에서 `refresh-us-common --max-new 10` 형태의 별도 명령과 마감 후 전용
Actions 단계를 추가하고, 위 승격 게이트의 테스트를 먼저 작성하는 것이 안전하다.
기존 전체 시딩 경로는 재해복구용으로 유지한다.

## 2. 상태 영속·복구 (계좌가 안 날아가는가)

| 문제(오류) | 개선 | 효과 |
|---|---|---|
| 계좌·수집분이 actions/cache 단일 의존 — 경합으로 소실(A1) | 원자적 저장(본파일) + **`.bak` 이중 저장** | 저장 중 중단에도 복구 가능 |
| cache는 7일 미사용 소멸·임의 evict 위험 | **state 브랜치** 스냅샷 + 월별 append-only 원장 | cache 밖 source of truth — 계좌 리셋 원천 차단(7/7 12:23 첫 가동) |
| 복구 우선순위가 불명확 | 복구 체인 확정: **본파일 → .bak → state 스냅샷 → 새 계좌** | 어느 층이 죽어도 다음 층에서 복원 |
| state 브랜치가 로컬 테스트에 운영 계좌를 끌어옴(사건 C) | `_state_branch_snapshot`을 **`GITHUB_ACTIONS=true`에서만** 실행 | 테스트 격리 회복 |

## 6. 보안 (유출·오용에 강한가)

| 문제(위험) | 개선 | 효과 |
|---|---|---|
| PAT 유출 시 피해 범위 | fine-grained PAT: **Actions RW·1개 repo·90일 만료** | 유출 시 피해 상한을 '빌드 강제 실행'으로 축소 |
| 외부 dispatch로 무거운 full 남발/오발사 | `full`은 **`confirm=FULL`** 없이는 거부 | 비용·부하 오용 차단 |
| 폭탄 dispatch 공격 | guard의 신선 시 no-op | 최악이 '공회전'으로 축소 |
| 실거래 손절 봇에 매수 경로가 섞일 위험 | **sentinel에 매수 경로 부재**(소스 grep 테스트로 영구 검증), 키는 env 전용, 기본 dry-run | 오주문·키 유출 표면 제거 |

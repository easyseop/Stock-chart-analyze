- **조치**: 외부 크론(cron-job.org)이 이미 이중화층으로 가동 중이라 실피해 0.

### B7. MCP App 머지가 push 트리거를 안 함 (7/7, 심각도: 낮음 — 지속)

- **원인**: MCP GitHub 도구의 squash 머지는 **GitHub App 설치 토큰**으로 커밋
  (committer=`GitHub <noreply@github.com>`) → App/봇 토큰이 만든 push는 무한루프 방지로
  워크플로를 트리거하지 않는다(GitHub 공식 동작). `[skip ci]`나 outage가 아님.
  ※ docs만 바뀐 머지가 안 도는 건 별개로 **정상**(push의 paths 필터에 docs 없음).
- **영향**: 낮음 — push 트리거는 '즉시 재배포(~2분)'용. 안 떠도 다음 크론(≤15분)이
  기본 브랜치 HEAD를 체크아웃해 새 코드를 반영. 단 `[update-top]` 푸시 탈출구도
  MCP 머지로는 안 뜨므로, 강제 신선 빌드는 외부 dispatch(cron-job)로 대체.
- **실거래 전 방어(권고, 미구현)**: state feed에 `last_deployed_sha` 기록 → 외부
  크론이 기본 브랜치 HEAD와 비교, 10분+ 다르면 `dispatch(update=none)` 자동 재배포.
  push를 믿지 않는 구조.

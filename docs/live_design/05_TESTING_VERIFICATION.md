# 파일 05 — 테스트 · 실측 검증

> 읽는 법: `##` 하나씩. 이 파일은 "코드가 맞나"(VH)와 "실제 토스가 우리 가정대로
> 동작하나"(VR)와 "계좌 자체가 준비됐나"(VA)를 다룬다. **VR은 Stage 2 Go의 관문** —
> 여기 통과 못 하면 파일 02·03은 배포 금지.

---

## VH — 장애주입 테스트 하네스

- **무엇**: 주문 경로(O2·O3·X1·X4)에 **timeout·429·5xx·부분체결·토큰만료·409중복·422거부**를
  주입해 원장·대사·잠금이 올바르게 반응하는지 검증하는 테스트 하네스.
- **왜**: Stage 2 게이트가 "장애주입 통과". 실계좌 사고는 정상경로가 아니라 **경계(응답
  못 받음·부분체결·정정실패)**에서 난다. 유닛 목만으로는 부족 — 시나리오 조합을 강제 재현.
- **어떻게**: mock 브로커에 시나리오 스크립트 주입(`FaultBroker`): 예)
  "place→timeout(UNKNOWN)→종목잠금→부팅대사에서 부분3 확인→잔여만 재주문→filled".
  각 시나리오가 **초과매도 0·이중주문 0·무방비 포지션 0**을 단언. 토스 **샌드박스/모의계좌
  있으면 통합테스트로 승격**(실측 VR과 결합), 없으면 목 기반 유지 + 소액 실계좌 1건으로 보완.
- **주의**: 이 하네스는 기존 `test_ledger`·`test_sentinel` ⑧을 **확장**(재작성 아님).
  "정상 통과"가 아니라 "고장에서 안전"을 본다.
- **테스트(자기 자신)**: 각 fault 시나리오가 기대 종단상태에 도달.
- **의존/Stage**: O1~O4, X4 / Stage 1.5→2 게이트.

## VR — 실측 런북 (V1~V3, 네가 실계좌로 실행)

- **무엇**: 코드가 아니라 **네가 토스 실계좌로 확인**하는 절차서. 각 항목에 "무엇을·어떻게·
  성공기준·안전설계"를 명시.
- **왜**: 우리 설계의 여러 [대조필요]는 실제 응답으로만 답할 수 있다. **추정 금지 원칙**의
  실행부. 특히 아래 4종은 Stage 2 No-Go 해제 조건.
- **어떻게(절차)**:
  - **V1 (Stage 0)**: `python -m bot.toss --selftest AAPL,005930` → 토큰·시세 확인.
  - **V2 그림자 4종 (Stage 2 관문)**:
    1. **UNKNOWN 대사**: 아주 작은 주문 후 orderId를 "모른다" 가정 → clientOrderId·symbol·
       기간·holdings 변화로 찾아지나?(안 되면 **No-Go**)
    2. **OCO/SINGLE STOP 시장가 체결**: US 종목 STOP+MARKET 조건주문 생성되나·트리거 후
       실제 시장가 체결되나(안 되면 B0b로 강등, 파수꾼 의존).
    3. **clientOrderId 10분 창**: 같은 값 1분 내 재요청=동일결과 / 다른 body=충돌 /
       11분 뒤=새 주문 여부(안전한 거부될 주문으로 설계).
    4. **조건주문 sellable 선점**: 조건주문 등록 후 sellable 감소하나?(파수꾼 충돌 정책 결정)
  - **V3**: 429 응답 헤더(Retry-After/한도), accountSeq 형태, 매수후 sellable 반영 타이밍,
    환전 동작(X3), API 점검시간.
- **주의**: 모든 실측 주문은 **거부되거나 극소이거나 즉시 취소 가능**하게 설계(V2 실험을
  실제 리스크로 만들지 말 것). 결과를 `TOSS_API_READINESS.md` §9/§14에 갱신.
- **의존/Stage**: 키 설정 후 / Stage 1.5(관문).

## VA — 계좌 설정 확인 (네 몫)

- **무엇**: 코드가 아니라 **토스 계좌·앱키 설정**이 실매매에 맞는지 확인.
- **왜**: 미수/신용이 켜져 있거나 미국주 거래·조건주문 권한이 없으면, 코드가 아무리
  맞아도 주문이 거부되거나 의도치 않은 레버리지가 붙는다.
- **어떻게(체크리스트)**:
  - 미수/신용 **비활성**(현금 주문만) · 미국주 거래 권한 · 조건주문 사용 가능 여부 ·
    앱키 권한 범위(읽기전용 스코프 존재? — I4/깃 키 분리와 연결) · **IP allowlist 유무**
    (있으면 상시 서버 고정 IP 등록) · 계좌 1개만 주문 대상으로 명시(LIVE_ACCOUNT_SEQ) ·
    앱 수동주문 금지 원칙 합의.
- **주의**: 이건 개발이 아니라 사전 조건 — Stage 2 전에 네가 확정. 하나라도 불명이면 그
  범위는 Stage 2에서 제외(예: US 권한 불명→KR만).
- **의존/Stage**: (사용자) / Stage 2 전 필수.

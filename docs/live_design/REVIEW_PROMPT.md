# 토스 실주문 설계 검토 요청 (Codex/GPT 리뷰어용)

## ⚠️ 읽는 법 (반드시 지켜라 — 컨텍스트 손실 방지)
이 설계는 6개 파일이다. **절대 한 번에 다 읽고 총평하지 마라.**
1. `00_OVERVIEW.md` 먼저 읽고 아키텍처·불변식·Stage 게이팅을 파악.
2. 그다음 `01 → 02 → 03 → 04 → 05` 순서로, **파일 하나씩** 연다.
3. 각 파일 안에서 **`##` 태스크 하나만 읽고 → 그 태스크만 판정 → 다음 태스크**로.
   한 태스크는 What/Why/How/주의/테스트/의존으로 자기완결이니 그 단위로 본다.
4. 파일 하나를 끝내면 **중간 요약(그 파일에서 채택/수정/기각 목록)**을 내고 다음 파일로.
5. 모두 끝난 뒤에만 전체 종합 판정을 낸다.

## 너의 역할
너는 국내 증권 Open API로 **실계좌 자동매매를 운영**해 본 시니어 트레이딩 인프라
엔지니어다. 아부·요약 칭찬 금지. **"이 태스크는 이 순서로 이렇게 깨진다"는 구체적
실패 시나리오**만 가치 있다.

## 배경 (핵심만)
- 차트 전략(52주 저점권 전환 초입 매수·ATR 손절·손익비 1:2·일봉 스윙) → 토스 실계좌
  자동매매가 목표. 시드 1억, 종목당 1/3, 1% 리스크. 유니버스 ~5,400(95% 미국주).
- 현재: GitHub Actions 무료 배치 + CF Worker + 매도전담 파수꾼(dry-run)으로 **가상
  모의투자**. 토스는 **시세 읽기 전용(Stage 0)** 어댑터까지 구현. 실주문 0.
- 이미 구현된 골격(재작성 대상 아님): `bot/toss.py`(시세·토큰·`classify_error`·
  `client_order_id`), `bot/ledger.py`(주문 원장 5상태·UNKNOWN 잠금·대사·잔여),
  `bot/sentinel.py`(파수꾼 dry-run·포지션 멱등키·원장연동, 실주문은 NotImplementedError),
  `scanner/autopaper.py`(모의매매·kill-switch L1), `bot/notify.py`(ntfy P0 이중화),
  `infra/cf-worker`(발사·검증·SHA 자가치유).
- 관련 사실정리: `docs/TOSS_API_READINESS.md`(스펙 전수 파싱 + 이전 GPT 5부 검토 반영,
  특히 OCO를 "보조 방어"로 강등한 §7 등급화).

## 각 태스크마다 판정할 것
`채택 / 수정채택 / 보류 / 기각` 중 하나 + 근거 + (수정채택·기각이면) 구체적 실패
시나리오와 대안. 특히 다음을 집요하게 봐라:

1. **초과매도·이중주문**으로 깨지는 지점 — UNKNOWN·부분체결·정정실패·부팅 대사·
   clientOrderId 10분 창에서. (O1~O4, X4가 핵심.)
2. **보호 공백** — 매수→보호주문 등록 사이, expireDate 만료, 조건주문 sellable 선점,
   파수꾼과 조건주문 상호 차단. (P1·P2·L6.)
3. **매수 실행 경로(X1·X2·X3)** 의 사이징·환전·체결가 왜곡, 신호 feed 지연.
4. **아키텍처 불변식** 위반 — 깃에 주문키·루프별 토큰·계좌 자동선택·강제청산.

## 전체 종합에서 반드시 답할 것
- **Q1. 빠진 태스크가 있나?** (우리는 26개로 봤다. 실계좌 운영에서 이 목록에 없는
  치명 함정 — 정산/세금 기록, 미수/증거금, API 점검, 주문 체결 폴링 형태, 트레일
  stop 동기화, 주간거래(dayMarket) 등 — 을 지적하라.)
- **Q2. 순서·의존이 틀린 곳은?** 특히 "V2 실측 전 착수 금지"로 묶은 게 맞나, 더 앞당길/
  미룰 태스크는?
- **Q3. 기존 골격과 중복(재작성)하려는 태스크가 있나?** (있으면 "확장/연결로 바꿔라"로.)
- **Q4. 과설계(모의·소액 단계엔 불필요)한 태스크는?**
- **Q5. Stage 2 Go/No-Go 관문(특히 UNKNOWN 대사 실측)이 충분한가?**
- **Q6. 가장 위험한 태스크 3개**와 그 이유(구체 시나리오).

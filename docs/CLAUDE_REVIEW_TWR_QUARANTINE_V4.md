## 1. Codex V3 지적별 대응

### P1-1 슬리브 미확정 값이 account에 확정 → 전파

`account = A + B`인 종속값이라는 지적을 수용했다. `_twr_step`에서 A 또는 B가
격리되면 `account`도 함께 `unresolved`에 넣는다(독립 총 NAV 원천이 생기기
전까지). 마감 행은 `acct=None`·`b`만 확정, carry는 account 미확정이므로 다음
세션 계좌·지수가 같은 첫 표본 0%로 재시작한다.

**결함을 '정상'으로 고정하던 테스트 2건을 Codex 반례 계약으로 교체했다**
(`test_close_keeps_per_key_values...`는 acct 확정을 assert하고 있었다).

### P1-2 perf.html 누적 알파 단순 합 → 복리

`cum += acct - idx`를 계좌·지수 **각각 복리** 후 차이(`(aw-iw)*100`)로 교체.
계좌 또는 지수 결측일 이후로는 잇지 않는다(broken flag 유지).

### P1-3 지수 결측일 암묵 0%·주 지수 대체

- `series[i][2]`와 `days[].idx`는 **주 지수 전용**: 주 지수가 그 틱에 실제
  수집됐을 때만 기록, 결측이면 `None`(S&P500이 나스닥으로 둔갑하던 경로 제거).
- 마감: 주 지수 결측이면 "지수 대비 판정 보류" 문구, `days[].idx=None`,
  `capture_stats` 표본 제외+표기.
- 사이트 기간 누적: 결측 검사를 `idx:*` 키까지 확장 — 기간에 결측이 하나라도
  있으면 그 지수 누적을 숫자로 확정하지 않음.
- 차트: 결측 지점 pen-up(전후 미연결). 세그먼트 종료가 결측일 때도 이전
  구간이 사라지지 않게 `drewAny` 분리.

## 3. 남은 격차 — 정직하게

1. **P1-2의 복리 테스트는 Python/Node 자동 테스트가 아니다** — perf.html
   인라인 JS라 수동 검산만 했다(+10/+10→+21.00, +10/-10→-1.00). 렌더
   테스트 요청.
2. **account 독립 원천은 도입하지 않았다** — 전파는 보수적 우회이지 근본
   해법이 아니다. 슬리브 격리가 잦으면 계좌 곡선이 자주 미확정이 된다.
3. **outbox 재시도는 `_deliver_close_alert` 경로만** — 장중(mid) 알림은
   실패 시 다음 주기 재평가로 재시도되지만 전달 상태를 영속하지 않는다
   (프로세스 재시작 시 그 주기 알림 1회 유실 가능).
4. P2-5의 400일 상한도 여전히 절단이다. append-only 별도 원장은 미도입.
5. 세그먼트 ID 미도입(V3와 동일) — "기간 비확정 표시" 방식 유지.

## 4. 검토자 확인 요청

- P1-1 전파 후에도 **hold 단계(격리 전 ≤3틱)** 동안 의심 변화가 account에
  일시 누적되는 것이 허용 수준인지(격리 시점에 세션값이 미확정으로 바뀌므로
  최종 표시·기록에는 남지 않지만, 장중 중간 표시엔 잠시 보인다).
- perf.html 복리 전환이 KPI·범례·캡처 문구와 정합인지 실제 렌더로.
- 시장별 400행 보관이 상태 파일 크기·ntfy 4KB 한도와 충돌하지 않는지
  (`publish_dash`는 여전히 30행만 발행).
- 주 지수 결측 처리로 **KR 시장**(코스피 주지수) 경로에 회귀가 없는지.
